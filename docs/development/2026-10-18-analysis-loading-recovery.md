# 分析工作区加载失败与空状态修复

## 问题与原因

分析工作区出现“加载失败”“样本范围加载失败”，但主区域显示“暂无已发布分析数据”。核查发现，常规前端代理指向的 `8000` 后端未运行；此前参考资源验收使用的临时后端不属于常规服务入口。数据目录仍有已发布数据，不能据此判定数据缺失。

原页面在处理目录请求错误之前判断空数组，而查询尚无返回值时默认提供空数组，导致连接失败被表现为空数据。

## 修复范围

- 恢复常规后端 `8000` 和前端 `3000` 服务；未重新导入或修改科研数据。
- 数据集目录、分析运行目录请求失败时优先展示“分析数据加载失败”，重试同时重新请求两份目录。
- 只有两份目录均加载成功、且数据集目录为空时，才显示“暂无已发布分析数据”。
- 两个目录接口校验返回值必须为数组，避免异常响应被误认为空目录。
- 开发和预览代理统一支持进程环境及 Vite `.env` 中的 `VITE_API_PROXY_TARGET`，进程环境优先，默认仍为 `http://127.0.0.1:8000`。
- 上游连接失败返回带有明确说明的 JSON / HTTP 503，不自动切换其他后端。

- `npm run lint`、`npm run typecheck`、`npx vite build --configLoader runner` 通过。
- 浏览器验收脚本：`frontend/scripts/verify-analysis-loading.mjs`，确认真实丰度 Canvas 绘制完成；模拟目录请求 503 后显示错误、重试恢复实际图表；成功空目录保留空状态；隔离代理对未监听上游端口返回结构化 503。
- 截图位于忽略目录 `frontend/.tmp/analysis-loading-qa/`。
- MAG 导航回归测试等待初始图表及 URL 选择就绪后再切换工作区，消除初始化与导航之间的测试时序冲突。
