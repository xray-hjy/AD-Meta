# KO 功能类别组成后续开发提醒

## 当前边界

当前正式实现是“高丰度 KO 相对贡献”，不是 KEGG 功能类别组成：

- 每个样本先在 `Sample × KO` 矩阵内做总和归一化，再计算所选样本范围内的组均值或单样本贡献。
- 所有可见序列使用同一套排名，Top N 仅限制浏览器绘制数量。
- 未进入 Top N 的 KO 仍保留在完整结果和投影审计明细中，不合并为 `Other`。
- 图表披露各序列 Top N 的累计覆盖率、来源 KO 数量和未展示 KO 数量。

这样可以解决旧图中 `Other` 超过 90% 而掩盖主要 KO 的问题，同时不虚构尚不存在的功能类别语义。

## 为什么暂不实现类别组成

KO 编号本身不是唯一的功能类别。要按 pathway、module 或 BRITE 层级汇总，必须先引入可复现的 KO 注释映射，并明确一对多归属如何计量。当前仓库没有满足这些条件的版本化映射产物，因此不能仅凭 KO 名称在前端临时分组。

参考入口：

- [KEGG ORTHOLOGY](https://www.kegg.jp/kegg/ko.html)
- [KEGG BRITE](https://www.kegg.jp/kegg/brite.html)
- [KEGG API](https://www.kegg.jp/kegg/rest/keggapi.html)

## 后续正式实现要求

1. 在 Analysis Artifact / Manifest 中增加版本化的 `ko_annotation_mapping` 产物，至少记录来源、版本或获取日期、许可证说明、校验和及生成流程版本。
2. 映射表至少包含 `ko_id`、目标体系、类别路径、类别标识和类别名称；不得把 pathway、module 与 BRITE 混为同一层级。
3. 明确一对多映射策略：重复计入、按归属数分摊或只选主类别。默认方案必须满足质量守恒，并在图表和导出元数据中披露。
4. 明确未注释 KO、无效 KO 和映射版本缺失时的处理方式；未注释项不能静默丢弃。
5. 后端新增独立的类别组成投影与审计栏目，前端新增独立图表，不复用 `ko_contribution` 的名称或语义。
6. 增加质量守恒、映射覆盖率、一对多归属、未注释项和版本变更的测试，并提供完整明细与论文级导出入口。
