# 20261020 更新：MAG 队列化接入与版本包退役

本次将 MAG 的应用数据管理从 `mag_vN` 版本包和专用关系表调整为稳定队列、可独立修订的来源模块及分析发布记录。目标是让 MAG、既有物种和群落 KO 关联到同一研究队列，同时保留各模块自己的数据来源和统计口径。此项改动只处理已产出的分析结果，不执行 FASTQ 质控、组装、分箱、基因预测或 DRAM2 功能注释。

## 队列与原文件归档

- 稳定队列键为 `prjca022804-ad-nc`，对应 PRJCA022804 / CRA014435 当前使用的 185 个 AD/NC 样本；样本标签为 AD 122、NC 63。队列身份独立于某一次工具运行或 MAG 数据版本。
- 从用户整理的服务器交付目录复制并核对 3,440 个 MAG 来源文件，共 1,126,012,366 字节。另保存文件说明和 SHA-256 清单；源目录未被本次整理改写。
- 原始 MAG 文件和共享样本元数据放在 `backend/storage/raw/`。大型输入由硬盘分发，Git 仅收录说明与清单；物种、KO 小型数据继续使用既有仓库管理方式。
- `backend/storage_manifest.json` 声明队列样本来源、模块输入、必需项和解析器。导入时逐模块校验文件哈希、样本 / MAG 身份和工具产物；raw 文件保持只读，结果查询从数据库读取。

## 数据库与运行方式

- 新增 `cohorts`、`cohort_releases`、`cohort_artifact_revisions`、`cohort_artifact_records`、`cohort_mag_abundances` 和 `cohort_import_jobs`，分别管理队列身份、发布引用、模块修订、结构化记录、稠密丰度和导入过程。
- 一个队列可有多次不可变分析发布；每次发布绑定模块修订以及关联的物种 / KO 数据修订。样本标签冲突、必需输入缺失或身份校验失败时不发布；可选模块单独记录状态，不会把缺失结果补成零。
- 新增 `import:cohort`、队列数据校验、raw 归档核验和运行时首次导入支持。服务重启不会重新导入已有发布；结果 API 按队列与发布指纹读取数据库。
- Alembic `20261020_01` 创建队列表；`20261020_02` 按外键依赖顺序删除旧版本包的十张 `mag_*` 表。旧 `20260912_01` 修订保留为迁移链兼容占位，不再创建旧表。物种、KO 和 `cohort_*` 数据不在删除范围内。
- 删除旧 MAG 数据加载器、数据库加载器、`mag_v2` 准备命令、旧导入别名、旧版 DDL 和依赖这些实现的测试。前端继续通过 `/analysis/mag` 使用队列 API。

## 明确未完成的内容

- DRAM2 步骤仍在运行，本次归档和可视化接入不包含 DRAM2 最终功能注释。MAG 级 KO、CAZyme 等功能归属未完成，群落 KO 丰度不能替代 MAG 功能注释。
- 当前没有通过 crosswalk 将 MAG 可靠映射到群落物种特征，因此不展示伪造的跨模块功能或分类对应。
- 本次不复制代表 MAG 全序列 FASTA、dRep 大型 Mdb 表、工具数据库和临时计算目录。它们不影响本次已接入的结果；若后续新功能确实需要，再按模块补充来源与存储策略。
- 页面中的组间统计属于当前队列的探索性描述，不构成因果结论、临床诊断或已验证生物标志物；年龄、性别或批次筛选本身不等于协变量校正。
