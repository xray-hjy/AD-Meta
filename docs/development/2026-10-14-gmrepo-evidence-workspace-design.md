日期：2026-10-14。方案版本：1.0。状态：后续开发实施基线，业务功能尚未实施；科研规则和发布结果按 SOP 复核。

实施更新：同日已完成技术首版，见[首版实施记录](2026-10-14-gmrepo-evaluation-implementation.md)。本文保留原设计状态的历史说明，实际完成度以实施记录及真实验收为准；科研复核、完整检索与数值复现并未自动完成。

后续增量规划见[2026-10-15 迭代方案 v1.1](2026-10-15-gmrepo-evidence-next-iteration-plan.md)：以当前实现为起点，按研究台账、对象解释、复核发布及条件化能力扩展推进，不重复建设已完成首版。

本文件是后续优化现有 GMrepo 模块的主实施方案；[SOP](2026-10-14-gmrepo-evidence-sop.md)是其流程附件。产品方向已依据本次讨论收敛，后续直接按本方案开展开发和验收。数据获取、分类核查和科研复核的实际状态须单独留证，不能因设计定稿而标成已完成。

同日讨论修订：将 GMrepo 内 AD 相关研究的系统性发现、现有 13 项与源库清单的差异核对，以及 16S/WGS 可用性审查前置到第一阶段。现有 16S 快照可支撑页面开发，但不能替代接入范围建设；WGS 发现和可用数据获取属于接入建设，数值复现仍依据科学条件开放。

流程补充：[GMrepo AD 外部参考证据接入与发布 SOP（设计稿）](2026-10-14-gmrepo-evidence-sop.md)定义 S0–S7 的输入产物、通过条件、复核与评审交付要求。正式实施先冻结研究问题/纳排/方法规则，再开展 A0 检索，避免根据结果挑选外部证据。SOP 尚未执行完毕，不代表认证或评审通过。

本方案结合本次讨论、项目商业计划书、上游生信流程、现有 GMrepo 数据包和前后端实现制定。用户已明确：保留现有可视化能力，布局可以重做；证据应拥有无侧栏的完整工作区，不采用候选旁边的紧凑面板；必须与已有主分析可视化贯通。本文定义待开发的页面、字段和接口，不代表已上线能力。

## 1. 目标与产品定位

将当前“GMrepo 参考数据”优化为微脑智库的正式外部证据评估模块。研究者能够从已有可视化中的一个主分析对象出发，携带原分析版本和范围进入完整评估，判断外部研究观察到了什么、哪些结果可比较、哪些尚待核查，并追溯到具体队列、样本范围和来源，再回到原图继续研究。

项目核心仍是 AD 脑肠轴研究中的物种、群落功能和 MAG 多层级数据组织、候选特征探索及综合解释。GMrepo 主要提供人群和分类丰度层面的外部背景。微脑智库负责来源审查、与本项目对象的可靠关联、按研究问题组织证据和展示边界。

产品名：**外部证据评估**。来源名称：**GMrepo AD 相关参考快照**。页面同时展示数据获取日期、处理版本和实际覆盖，不把本地处理版本写成 GMrepo 官方 release。首页/主分析导航中的现有 GMrepo 入口沿用并更新名称，GMrepo 来源在模块内始终可见。

首版完成后的研究路径：

```text
主可视化中的物种/MAG对象 ── 外部证据评估 ──────┐
                                              ↓
GMrepo 菌属目录 ───────────────────── 全宽证据工作区
                                              ↓
                             证据摘要 → 队列比较 → 分布检查 → 来源追溯
                                              ↓
                                    返回原分析 / 导出证据记录
```

首版承接的是当前可选分析特征，不能把所有特征预先叫作 AI 候选。正式模型候选结果交付后，再复用同一工作区。首版验收必须覆盖真实物种对象的贯通和 MAG 的可靠对应/缺项路径，不能只增加顶栏跳转链接。

## 3. 页面与信息架构

采用同一模块下的两类页面：**参考资源目录**、**研究对象证据详情**。前者回答接入范围，后者回答某个对象的外部证据。共享顶部导航、检索、版本信息和视觉语言，均采用无侧栏布局。

### 3.1 参考资源目录

保留 `/reference/gmrepo` 作为稳定入口。顶部页签为“参考资源”和“对象证据”；没有选定对象时，后者先提供菌属检索，不自动制造某个对象的结论。

内容顺序：

1. 模块介绍与简短快照信息：用途、平台、日期和来源。
2. 队列目录及纳入状态：研究项目、原研究、疾病阶段、平台、profile 可用性、AD/NC 分布资格、检验资格、独立性状态。
3. 数据覆盖与质量可视化：保留各队列 AD/NC、纳入状态、年龄/性别可用性、分类待解析比例四类图。允许使用局部双列，不形成固定侧栏。
4. 参考样本查询：沿用队列、分组、范围和可选菌属列；零值、缺失、阶段参考等原语义保留。
5. 来源与版本详情：获取清单、处理说明、发布历史、可用证据与缺项。

目录首版纳入系统检索中“发现但未接入”的研究项目，交代获取、处理和排除状态。检索尚未完成时只写“当前快照覆盖”；建立并核实检索范围、去重清单和固定快照后才发布对应覆盖指标，不使用假设的总项目数。

### 3.2 研究对象证据详情

路由采用两种入口：`/reference/gmrepo/evidence/:genusId` 直接打开已知外部属；`/reference/gmrepo/evidence` 接收主分析对象后先解析对应关系。主分析上下文通过已验证的查询参数附带。无法解析时仍进入完整的对应状态页，解释具体缺项，不跳到默认 Bacteroides。首版外部证据对象仍是参考菌属；上方同时显示来源物种/MAG 对象和映射层级，避免混淆。

```text
┌────────────────────────────────────────────────────────────┐
│ 微脑智库   外部参考与证据   参考资源 / 对象证据   返回分析    │
├────────────────────────────────────────────────────────────┤
│ 研究对象、所属分类、来自哪个分析版本、参考版本、导出        │
│ 顶部页内导航：证据说明 / 队列比较 / 分布 / 核查 / 来源       │
├────────────────────────────────────────────────────────────┤
│ 综合证据说明：实际观察、可评价范围、冲突、缺项              │
│ 主数据对象与 GMrepo 菌属之间的对应关系及层级                │
├────────────────────────────────────────────────────────────┤
│ 外部队列比较：全宽表格；点击一行选择下方研究队列            │
│ 可用时展示按方法分开的队列效应图                           │
├────────────────────────────────────────────────────────────┤
│ 所选队列的菌属分布：全宽箱线与散点、尺度切换、统计说明     │
│ 全部样本明细、参与者与协变量核查                          │
├────────────────────────────────────────────────────────────┤
│ GMrepo 来源 marker、原研究、处理方法、版本和导出            │
└────────────────────────────────────────────────────────────┘
```

内容纵向阅读。正文说明采用适当文字宽度；证据表和主要图表使用完整内容宽度。顶部页内导航可轻量吸附，不能遮挡标题、图表工具或移动端内容。通过段落、留白和细分隔线建立层次，避免大量独立 KPI 卡片铺满首屏。

默认显示摘要、对象关系和队列比较。主体分布图保持可见；详细样本、技术参数和文件校验展开读取。折叠用于管理细节，不能隐藏“暂缓检验”“分类不对应”等影响判断的事项。

### 3.3 主分析贯通

首版在实际拥有特征对象 ID 的物种选择器、可操作结果行和 MAG 详情入口增加“外部证据评估”。主分析各图沿用原数据和操作；单对象入口复用统一关联逻辑，不在每个图组件重复分类匹配。

入口传递对象类型、稳定 ID、主数据 revision、AnalysisRun/Artifact（存在时）、分析范围和返回位置。显示名称仅用于展示，服务端根据 ID 解析真实分类。

主分析中的样本筛选、Top N 和单组展示作为来源上下文记录，不能悄悄改变外部 AD/NC 检验的样本集合或 FDR 检验族。返回主分析恢复原选择和筛选。固定版本不可用时明确提示，不能静默替换为新版本。

仅从 GMrepo 目录进入时允许没有主数据对象；外部证据可以独立浏览。主数据库不可用时，只将主数据区域标记为不可读取，不能连带关闭可用的参考包。

#### 3.3.1 现有可视化的具体关联

| 当前入口 | 用户操作 | 传递对象及进入后的行为 | 首版要求 |
| --- | --- | --- | --- |
| 物种箱线图及其特征选择 | 选定一个物种，点击外部证据评估 | 固定物种 ID/revision，展示主图范围及所属属的外部结果 | 必须贯通；多选先明确选择本次评估对象，不能任取第一项 |
| 物种丰度/差异图的可操作特征明细 | 在具体特征操作中选择评估 | 使用与箱线图同一对象解析器；可保留原图选择及滚动位置 | 复用统一入口，按现有稳定对象字段接入；不能只传名称 |
| 完整物种结果查询 | 从结果行的特征 ID 进入 | 带 run/artifact/revision，重复样本行指向同一物种对象，保留查询状态 | 必须提供可操作入口；不把单个样本行升级为该物种总体差异 |
| MAG 详情的分类证据 | 选择外部证据评估 | 优先读取已有 crosswalk；通过已核对 NCBI 分类路径确定属，保留 MAG 和代表/成员关系 | 必须接入；映射缺失时进入缺项说明页，不能靠删除 GTDB 后缀匹配 |
| 分类层级图 | 选中带有可靠分类对象的属/种节点 | 复用同一入口；显示节点层级与外部对应层级 | 稳定 ID 可解析时开放；节点文字不是对应凭证 |
| PCA/PCoA、群落概览等无单特征对象的图 | 从工作区入口检索研究对象 | 保留当前分析上下文，再明确选择物种/MAG | 不把排序坐标、样本或整群落直接关联某一菌属 |
| KO/功能图 | 有真实生物来源关联时进入关联对象证据 | 明示 KO → 物种/MAG → 外部属的链路及版本 | 真实归属链交付前仅显示能力说明，不制造 KO 的 GMrepo 直接证据 |

跨页面关联的核心是共享研究对象和版本，而不是共享相同配色或增加导航链接。主图筛选产生的是本项目观察范围；外部队列保留其审核后的比较范围，两者在详情里都能查看，不能隐式拼接。

#### 3.3.2 统一主分析上下文

定义一个共用对象引用，由主分析容器生成，服务端校验，所有入口复用：

- `subjectType`：species / genus / mag；功能对象仅在具备可靠归属后扩展。
- `subjectId`：源系统稳定 ID；前端展示名称不能替代。
- `datasetRevision` 或 MAG 数据 fingerprint、可用的 run/artifact key。
- `sourceChart`、当前筛选/选择与范围摘要；大范围条件使用受管上下文，不把全部样本/特征塞进 URL。
- `returnTo`：仅允许已验证的站内分析路径；原图状态通过路由或现有工作区状态恢复。

服务端解析主对象后，返回已核对对应、上一级背景、未解析、无参考覆盖或源版本不可用等状态；手工选取外部属必须标记为用户选择，不能改写自动映射的核查状态。主版本更新时重新解析，不复用其他版本的名称对应。

#### 3.3.3 两种可视化在详情中的关系

详情上方保留主对象的观察背景：来自哪个图/版本、使用何种样本范围、有何已存储的效应结果。主结果只有分类覆盖时如实显示；来源记录不足时不额外计算一套主效应。

中部以外部队列表和既有 GMrepo 箱线/散点为主体；双方图像可在用户选择后局部并排检查，但平台、单位、样本及分类层级分别标注，不能共用一个看似可比的丰度轴。来源图像截图只是展示附件，主对象和证据仍由数据与版本引用建立关联。

返回操作恢复原物种/MAG、图表、筛选和查询。浏览器后退、刷新及复制详情链接仍能解析相同对象；如果固定版本已不可读取，应说明原因，不静默换到当前版本。

### 3.4 图表保留与新增边界

现有四类质量图、箱线与散点、原百分比/log 展示、样本明细、统计目录和图像/数据导出能力均保留。完整菌属统计目录放在资源浏览的对象检索区域或详情的可展开目录，便于切换对象，不让 322 属大表打断单对象证据阅读。

后续队列效应图仅汇集统计资格通过的结果。未调整的秩二列相关和调整模型的百分位秩点差分别画图、分别标注单位；两者不能共用同一个数值轴。首版不绘制合并效应菱形、不汇总 pooled p/q。

移动端页签和锚点横向滚动、表格在自身容器滚动、图表完整占行，页面本身不横向溢出。色盲友好、键盘访问、文字状态和下载能力沿用。

## 4. 证据模型与判断规则

采用多个独立状态维度，而不是一条从“发现”到“验证”的线性等级或任意可信度分数。

| 维度 | 建议状态 | 作用 |
| --- | --- | --- |
| 对象对应 | 同层级已核对 / 上一级背景 / 未解析 / 无匹配 | 判断外部属能说明主物种/MAG的哪一层 |
| 数据可用性 | 完整 profile / 缺 profile / 无目标属信息 / 未接入 | 区分零值与不可评价 |
| 推断资格 | 可检验 / 仅描述 / 暂缓 | 判断能否显示统计结论 |
| 队列独立性 | 已核查 / 可能重叠 / 重叠已确认 / 未核查 | 决定能否计作独立外部队列 |
| 结果 | AD 偏高 / NC 偏高 / 无明确方向；另列 q 和区间 | 分开方向与统计支持 |
| 调整稳健性 | 同向 / 方向冲突 / 模型不可估计 / 未调整 | 说明调整前后结果，不把子集差异全归因于混杂 |

规则：

1. 一份证据记录绑定来源快照、队列、疾病比较、特征、样本范围和方法版本。来源 LDA、本项目重算、未调整/调整模型是同一研究的不同记录，不增加独立队列数量。
2. 多个项目 accession 可能来自同一原研究或复用同一受试者；需要关联研究标识及重叠审查。外部与主队列无相同 Run，也不足以认证完全独立。
3. 首版展示“可检验队列”和“方向分布”。跨研究独立性未认证时，不把它们命名为“独立验证队列”，也不发布伪精确支持百分比。
4. 将来发布同向比例时，明确比较对象、平台、方法、可评价分母、无方向结果和排除理由，同时列同向/反向中获 FDR 支持的数量。不能只挑显著研究构造一致性。
5. q 未通过阈值不等于不存在关联；未检出、未返回 marker、缺 profile 也不等于反证。
6. 调整前后当前使用的样本集合并不完全相同。摘要显示两套人数，方向变化称为“调整前后/分析样本变化”，不能直接断言年龄导致反转。
7. 来源 LDA 不作为本项目模型效应，不制造来源缺少的 p/q，不将混合 AD/MCI 比较转写为纯 AD/NC。
8. 搜索、分页、点选、图表尺度和布局变化不重算缩小后的 q，也不改现有统计方法。
9. 不足条件时输出具体缺项；“主数据分类覆盖”与“外部队列结果”可以同时存在，但不自动产生主数据数值复现结论。

摘要由后端规则生成，句子带依据 ID 和规则版本。首版不依赖自由生成 AI 来替代资格判断。例（仅示意，非当前结果）：

> 当前选中的是物种 X，外部参考对应其所属菌属 Y，因此提供属级背景。5 个队列有可展示分布，2 个具备队列内探索性检验资格；其中一项出现 AD 偏高且获 FDR 支持，另一项未获 FDR 支持。队列间独立性和主数据属级对照仍待核查。

## 5. 分类与功能关联

| 主分析对象 | 首版关联方式 | 可以说什么 |
| --- | --- | --- |
| 属 | 核对域、分类体系、当前名称、旧名和稳定 ID | 同属外部参考；能否方向对照另查方法与样本条件 |
| 物种 | 从发布版本读取所属属，映射到外部属；保留物种对象 | 该物种所属属的外部背景，不是该物种复现 |
| MAG | 首版接入详情入口，使用已有经审查 crosswalk 和可靠 NCBI 属路径；缺项返回对应状态 | 所属分类的外部背景；未解析映射不提供伪匹配 |
| KO / AMP | 仅在真实交付的特征 → 物种/MAG 归属链可用后关联 | 关联生物来源的背景；当前属丰度不证明具体功能或因果机制 |

当前 NCBI 内部 ID、项目 taxon_id 和 GTDB 名称不是同一套标识。映射记录需保留源/目标体系、release、层级、依据、审查状态；GTDB 字母后缀不能靠删字符或模糊名称自动认证。

首版可复用已核对属名匹配，但界面应标注“名称对应”而非“统一注释完成”。主数据属级重算需要确认原丰度单位、归一化、分类聚合、重复采样和协变量之后单独实施；当前物种差异方向不能直接与外部属方向作复现判断。

## 6. 接入方式与覆盖完善

采用**获取快照 → 原件留存 → 队列登记 → 分组/身份/分类审查 → 版本化处理 → 校验发布 → 只读服务**。在线接口用于读取发布数据，页面请求不执行源库下载和更新。

GMrepo v3 官方论文说明可下载整理后的元数据、分类 profile 和 marker 信息，适合作为规范化获取的起点；具体获取接口、授权范围和版本字段需在扩展时核对，不能沿用旧版 API 假定可用。[官方数据可用性说明](https://academic.oup.com/nar/article/54/D1/D734/8340991)

### 6.1 来源与覆盖登记

新增随版本发布的接入登记：

- GMrepo 官方版本（有证据时）、获取日期、URL/接口/下载文件、查询条件和检索词。
- 项目及原研究标识、平台、人体肠道样本范围、疾病阶段与分组定义。
- 发现、获取、处理、可展示、可检验的不同状态及排除理由。
- 获取批次、原文件哈希、处理脚本版本、taxonomy 版本和核查版本。
- 元数据字段级来源：GMrepo 原值、ENA、作者原表、论文解释、项目派生值分别记录。
- 原证据文件是否在运行包、是否仅在科研归档、是否只保留公开链接、是否缺失。

旧快照缺少的获取凭证先登记“待补”，不能倒填一个未经核实的来源版本。运行包哈希证明交付一致性；它不能单独认证数据最初如何从 GMrepo 获取。

### 6.2 版本发布

保持现有 2026-10-09-v1 原文件与 fingerprint 不变。新覆盖登记若作为首版补充，放在独立版本元数据中，绑定旧 fingerprint；新数据/分类处理则发布完整新目录与清单。

每次更新提供新增/移除队列、Run/profile 变化、分类映射变化、分组修订、资格和统计变化的差异说明。旧版本与证据导出保留，校验失败时不能用演示数据代替。

同步脚本与清洗/验证脚本可重跑、拒绝静默覆盖；获取失败记录真实失败。原科研归档需有持久保存位置、索引及校验，不能仅有处理清单而没有对应原件。当前运行包继续作为轻量部署交付，不承担完整科研归档职责。

### 6.3 数据扩展优先级

1. 首先系统检索 GMrepo 中 AD 相关研究：以 AD 标准表型 D000544、名称/关键词及原研究设计共同核对，向同项目配套对照和相关疾病阶段扩展。MCI、风险和临床前阶段单列，不默认都是 AD，也不只获取疾病标签记录而漏掉配套 NC。检索应使用完整导出或核实过的分页获取，搜索引擎结果和网页首屏不代表完整清单。
2. 将去重后的发现清单与当前 13 个项目逐项比对，列新增、已有、待核查、无法获取和排除项；关联原研究，区别项目数与独立研究数。补齐旧快照来源，核查 3 个“可画图但暂缓推断”队列的受试者关系。
3. 在同一轮同时审查 16S 与 WGS 数据可用性。有可下载且符合范围的 AD 相关 WGS profile 时纳入新版本的物种参考，不把这类数据统一推迟到页面建设以后；无可用项则记录检索和获取依据。平台类型结合 GMrepo、ENA 和原研究核实，不能仅凭 library_strategy 一列判定，当前包存在 RNA-Seq/OTHER 与来源 Amplicon 标注不一致的记录。
4. 有明确研究问题后再加入其他疾病背景，判断候选是否广泛变化；不预先认定 AD 特异性。
5. 方法、分类与独立性可比后再另行设计效应综合或外部模型验证。本次首版不宣称已完成。

## 7. 技术设计建议

### 7.1 在现有领域上扩展

继续复用 `gmrepo_service` 只读数据包、`gmrepo_analysis_service` 队列审查与统计、`gmrepo_primary_evidence` 主数据覆盖。增加聚合证据读模型和明确的主对象解析器，不复制主物种/KO/MAG 表。

新增聚合 API：`GET /api/references/gmrepo/evidence-summary`，读取所有可展示队列的某一菌属记录；另提供主对象解析 API，将经过校验的对象引用转为映射/缺项响应。输入绑定参考 fingerprint 与可选主分析上下文；主对象必须提供固定 revision。旧单队列 evidence、audit、distribution、statistics 等接口继续可用。

建议响应对象：

| 对象 | 内容 |
| --- | --- |
| `subject` | 外部属 ID、主分析对象及实际分类层级 |
| `mapping` | 对应方法、分类体系、依据、是否仅上一级背景 |
| `context` | 主数据 revision、run/artifact、原分析范围与返回上下文 |
| `reference` | GMrepo 官方版本可用性、快照、处理 fingerprint、覆盖登记版本 |
| `cohorts` | 人数、profile 状态、检验资格、原研究/重叠状态、两种模型、来源 marker |
| `summary` | 规则生成的观察句、依据 ID、计数分母和明确缺项 |
| `primary` | 分类覆盖、主版本及数值对照资格 |
| `provenance` | 方法/映射/核查版本、文件/链接证据可用性 |

聚合接口不一次返回所有样本散点；分布与样本明细仍按当前选中队列读取。参考版本变化返回明确不匹配，主版本/对象不存在提供可解释状态。

### 7.2 计算与性能

当前单队列 evidence 会调用完整属统计和所选属的 2000 次 bootstrap；直接并行重复调用 5 个接口会重复计算。新增聚合前先统一队列结果缓存。

完整属统计按参考 fingerprint、队列、核查版本和方法版本缓存/预计算，保存 p/q 的完整检验族。效应区间按特征缓存，按需生成；若聚合图未获得区间，则明确显示待计算，不能补成零或同步阻塞整个首屏。准备计算不额外改变估计方法。

主对象对应按主 revision/源哈希/映射版本缓存；摘要缓存还绑定跨队列独立性登记和规则版本，防止旧状态继续计数。目录与摘要先读取，重型图和样本明细按需加载；失败可局部重试。

### 7.3 前端与路由兼容

拆分 `ReferenceLibraryPage`、`FeatureEvidencePage` 及共用页头/对象选择/队列比较/来源组件，复用现有图表、表格和导出工具。定义共享主对象引用与 `EvidenceEntry` 入口，在工作区特征选择、完整物种结果和 MAG 详情复用；具体位置按现有组件接口接入，不将数据解析逻辑写入每个图表。证据页不挂主分析侧栏，主分析的其他布局不在本次范围内。

兼容旧 `view=genus`、`analysisCohort`、`analysisGenus` 链接，可解析为新对象页和所选队列；原概览 `group/scope` 不转成证据比较分母。跳转保留版本信息和站内返回上下文。

JSON 导出扩展为完整证据记录；新增 Markdown 可读报告。两者包含主/参考版本、样本范围、方法、映射层级、缺项和生成时间。首版复用图像导出，不新增复杂 PDF 流程。下载不得把未完成核查的结果写成“验证报告”。

## 8. 分阶段执行与验收

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| A0：AD 相关范围清点 | 固定检索范围和获取凭证、配套对照/疾病阶段、完整分页清单、16S/WGS 分类及可用性、与现有 13 项的差异 | 不把现有快照当成完整目录；所有发现项有获取/排除状态，未完成检索明确可见；优先获取真实可用 WGS 数据 |
| A：来源与证据契约 | 基于 A0 的来源/覆盖登记、状态维度、摘要规则、版本契约 | 能区分当前 13 项与新增覆盖、5 个分布队列、2 个核查合格队列；覆盖分母可追溯，无重复计票 |
| B：证据聚合与性能 | 主对象解析、固定版本聚合读模型、队列统计缓存和导出 | 名称不能伪造对应；缺失/无匹配可解释；版本隔离；主库不可用外部可读；不重复全属计算 |
| C：全宽界面与贯通 | 重构目录和详情、顶部导航、物种箱线图对象入口、完整物种结果入口、MAG 可靠对应/缺项入口、旧链接兼容 | 无侧栏；摘要/队列/图表/来源层次清楚；既有图表与交互保留；往返恢复主对象、版本和分析上下文；不能用顶栏跳转替代对象关联 |
| D：接入更新流程 | 可重跑获取/处理/校验脚本、科研归档索引、版本变化说明 | 新版本发布不覆盖旧版本，原件可追溯；当前来源缺项如实记录 |
| E：证据能力深化 | 持续更新 AD 队列、WGS 同层级数值对照、经审查 MAG 映射 | 基于前期取得的真实数据和核查能力开放；不把缺数据功能展示成已完成 |

首版交付范围为 A0、A、B、C，以及 D 的流程契约和现有档案缺项登记。A0 是必要接入建设，不能仅以现有快照页面改造替代；系统检索尚未完成或被外部获取条件限制时，应交付已发现范围和明确缺项，不宣称覆盖完整。页面原型可与范围清点并行，但新增 WGS 的单位、分类层级和样本规则需要独立验证。D 的完整旧快照重处理取决于原件/脚本能否恢复；若缺原件，交付中列明。E 的数值复现与功能关联后续按真实数据推进。

优先验证以下真实风险，不为纯布局逐项镜像写测试：

- 5 个可画图队列中只有 2 个开放当前检验；审核失败后摘要不得继续保留旧支持计数。
- 同一研究的来源 LDA/重算/调整模型不重复计票；项目 accession 重复研究、主外样本重叠有明确状态。
- 属级背景不升级为物种/MAG/功能验证；GTDB 未解析对应停留在未解析。
- q 和外部样本分母不随主分析筛选、分页、图表尺度改变。
- 零、缺 profile、无目标属、未返回 marker 保持不同状态。
- 主数据/参考版本固定；局部不可用、缺文件、返回旧上下文和深链接行为正确。
- 在桌面/平板/手机核对布局、键盘、色盲模式、全部样本点与现有导出；新增接口同步 OpenAPI/前端类型。
- 使用真实运行包核查 13/1269/800/322/5/420 的基线，冷读取及聚合读取有性能记录；不把示意统计作为实测结果。
- 主物种箱线图/完整结果中的同一对象解析到相同的外部属和固定主版本；多选不隐式取第一项；未匹配不回退到默认属。
- MAG 详情沿已有分类证据解析，成员/代表关系保留；没有可靠属路径时显示具体缺项；不将任意名称相似物种当成 MAG 对应。
- 原分析图、主范围、查询与外部范围均可追溯；打开详情、返回、刷新、复制链接和主版本切换行为正确。

当前工作树已有大量未提交修改，包括 GMrepo 页面/API、主分析导航和共用图表。实施前逐项识别重叠；基于当前工作树做增量修改，不覆盖用户已有成果，不回退其他模块布局。

## 9. 决策记录与后续实施入口

本次确定的实施方向：完整无侧栏证据工作区、资源目录与对象详情两类页面、保留现有可视化、规则可追溯的摘要、多个证据状态维度、固定快照的接入与更新流程，以及首版物种和 MAG 对象入口的可追溯贯通。科学数据缺项通过明确状态处理；后续 WGS/功能/模型能力按真实数据开放。

首版不依赖 AI 候选模型完成，也不以全量 GMrepo 镜像作为完成条件。研究者应能直接回答：选中谁、对应到哪一层、哪些队列可评价、观察到什么、为什么暂缓、原件在哪里。

实施时先展开 A0，基于发现清单完成 A/B 再接 C，获取来源审计与页面原型可并行。研究范围系统清点、WGS 可用性检查与可用数据获取从第一阶段展开；跨平台数值复现和功能关联以科学条件为准。本轮仅落设计文档与索引；业务代码、运行数据和统计规则均尚未因本方案变更。

### 9.1 代码落点与任务顺序

| 工作包 | 现有落点 | 交付与依赖 |
| --- | --- | --- |
| 规则/目录/来源 | GMrepo metadata、数据包 manifests、独立获取/审查 CLI | 执行 SOP S0/S1，版本化登记，旧参考包保持可读 |
| 主对象解析 | gmrepo_primary_evidence、主物种发布 revision、MAG lineage/crosswalk | 统一对象引用及对应状态；先完成稳定解析再接入口 |
| 聚合/缓存/摘要 | gmrepo_service、gmrepo_analysis_service、gmrepo API/models | 复用完整检验族与审核；方法/核查/映射/输入版本绑定 |
| 全宽页面 | pages/gmrepo、AppRouter、GMrepo API client | 重组已有图表，支持无对象检索、解析和已知属详情；旧路由兼容 |
| 主可视化入口 | AnalysisWorkspacePage、BoxplotFeatureSelector、CompleteResultsPanel、MagDetailDrawer | 共享入口及往返上下文；保护当前用户未提交改动 |
| 发布与演示 | 导出 CLI、现有 JSON/图像导出、针对性回归与真实案例 | 完成流程对账及主可视化 → 外部评估 → 返回的端到端验收 |

### 9.2 首版交付的定义

首版以“正式外部证据评估模块”交付，至少具备：按既定范围执行的 AD 资源清点及获取状态；可复核的证据记录和发布版本；完整全宽目录/详情；保留的 GMrepo 可视化；主物种真实贯通与 MAG 对应/缺项路径；带版本与局限的报告和案例。外部获取/科研复核未完成的部分有具体阻碍与记录，不能作为已完成项计入发布声明。

后续执行此方案时，不再以“做一个新的独立参考页面”作为结束条件。至少演示一个真实主物种从现有图表进入外部评估、查询来源和返回原图，以及一个 MAG 的可靠映射或诚实缺项路径；这些操作共同读取同一对象引用和版本契约。
