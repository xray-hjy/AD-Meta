# 2026-08-28 前后端开发分支交接说明

## 交接目的

本分支用于将当前可独立开发和验证的前后端成果交给组员继续开发。MAG 新数据仍需与生信组确认计算口径、样本映射和数据来源，因此本次不把原始数据作为正式系统输入，也不将本地原始数据文件提交到仓库。

分支基于当时最新的 `main`（`9de6e0e`）整理，前后端代码、必要测试和项目说明可先行交接，不必等待 MAG 数据契约全部确认。

## 已完成的前端工作

- 统一图表导出入口及导出行为，导出时排除 `dataZoom` 等仅服务于交互浏览的控件。
- 为适合直接导出的图表补充轻量导出操作，并保留门级组成等暂缓导出的特殊图表边界。
- 整理图表操作区、卡片动作区和图表内容区的布局关系，减少单图表临时样式。
- 引入统一品牌标识组件和项目 Logo 资源，完善首页与分析工作区的品牌展示。
- 更新分类层级图及相关测试，保持不同图表渲染器的既有功能。

## 已完成的后端工作

- 增加完整结果访问服务，为后续独立的完整结果分页查询和下载能力提供后端基础。
- 完善投影审计记录的生命周期字段、迁移和保留策略。
- 增加投影审计缓存复用及清理治理，区分长期默认结果与可淘汰的派生结果。
- 同步 API 模型、OpenAPI 描述及相关后端测试。

## 当前可继续开发的方向

组员可以直接在本分支继续进行以下工作：

1. 完善图表导出的文件命名、尺寸选项和格式提示，但不要把交互控件写入导出图像。
2. 在现有完整结果服务基础上实现前端分页查询与下载入口。
3. 继续统一图表卡片、动作栏和数据明细区，不在单个图表内追加孤立布局补丁。
4. 为新的分析模块复用现有 ChartFrame、导出动作和投影审计能力。

## 仍依赖生信组确认的事项

以下内容暂不作为正式产品输入：

- MAG 代表基因组、dRep 聚类、CheckM2 质量和 GTDB-Tk 分类之间的稳定 ID 映射。
- 185 个 CRR 样本与 MAG 丰度矩阵的完整样本映射及 AD/NC 元数据。
- CoverM 指标的命令、版本、过滤参数、单位和分母定义。
- MAG 相对丰度、平均覆盖深度、覆盖比例、read count 等指标的正式使用规则。
- 数据修订版本、计算软件版本和上游参数组成的 Manifest。

在这些口径确认前，可以开发接口和页面骨架，但不能把本地 MAG 文件或未经确认的统计量描述为正式分析结果。

## 本次明确不上传的本地资料

- `backend/storage/raw/crr-mag-quantification/`：生信组原始或中间 MAG 数据。
- `_notice_qa/`：本地视觉检查产物。
- `docs/reference/papers/`：本地参考论文文件。
- `docs/商业计划书.docx`、`docs/商业计划书.pdf`：本地成品文档。

这些文件不属于运行代码。需要共享时应通过项目约定的数据存储或资料渠道传递，不应混入开发分支。

## 验证与启动

前端验证：

```powershell
npm --prefix frontend test
npm --prefix frontend run build
```

后端验证：

```powershell
backend\.venv\Scripts\python.exe -m pytest backend/tests
```

本地启动仍使用仓库现有的本地启动工具；环境变量、MySQL 数据和派生缓存均为本地运行状态，不随 Git 分支传递。组员首次启动时应按项目配置初始化数据库并重新生成缓存。

## 项目表述边界

AD-Meta（比赛表述中使用“微脑智库”）是面向 AD 脑肠轴研究的肠道菌群研发辅助工具。系统当前以物种和 KO 分析结果为基础，并为 MAG 分析扩展预留结构。任何候选特征均应表述为研究线索，不得扩大为临床诊断、已验证生物标志物或因果结论。
