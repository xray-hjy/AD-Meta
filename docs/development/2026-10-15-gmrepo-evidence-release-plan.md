# GMrepo 外部证据评估：完整交付与科研复核方案

日期：2026-10-15。版本：1.3。状态：用户已确认执行；2026-10-16 已完成一轮来源补充、WGS 阶段参考与离线复算技术实现，科学证据仍有具体缺口。实际进展见[实施记录](2026-10-16-gmrepo-release-implementation.md)。

### 2026-10-16 产品边界修订（优先于下文原方案）

保持一套产品、一套页面，不区分对外版和内部版，不新增科研审核后台。组员线下核查后整理研究描述；页面呈现研究事实、结果、来源、比较范围与具体适用限制，不呈现人员签署、待审清单、资料补交任务或待审包入口。已实现的来源校验、范围绑定、历史更正及复算机制保留为结果可靠性保障，不作为用户必须操作的审批流程。移除过程展示不表示已有科研批准、独立性成立或限制解除。

接续[迭代二实施记录](2026-10-15-gmrepo-iteration-two-implementation.md)。本文将原研究补证、有效人工复核、重叠核查、WGS 分层接入、主数据语义与可重算交付纳入同一发布计划，不再以新增页面或统一 pending 文案作为完成目标。

## 1. 目标和完成边界

目标是交付一个可供科研人员实际使用、核查与复算的外部参考证据评估模块。用户从主分析候选出发，应能回答：哪些原研究可以参考、比较了什么人群和对象、实际结果是什么、来源和计算如何核验、哪些用途仍受限制。

完成不等于所有研究都获准检验，也不等于有显著结果或独立验证。资料不足、已知重叠、明确排除、只可追溯均是可以验收的处理结果，但必须有真实核查过程、具体依据和用途后果，不能用空白状态代替工作。

发布分别记录以下状态，不用一个“通过”覆盖全部：

1. 资料处理完成：约定检索范围执行完毕，逐项有原件、事实或无法取得的核查记录。
2. 技术发布通过：契约、来源、计算、页面、冻结记录和复算测试通过。
3. 科研意见已生效：真实人员对具体范围作出通过、限用、退回或不通过意见。
4. 限定用途获准：仅相应队列、比较、对象层级、版本和方法获准使用。

没有人员签署时可交付前两项和完整待审包，不能把整个科研流程标为完成。若未取得合格 WGS 数值数据，只能完成 WGS 发现/筛查，不能把此称为 WGS 数值接入完成。

## 3. 统一工作流

检索口径冻结 → 全量候选与纳排 → 原研究/样本/参与者关联 → 来源分层与比较契约 → 技术核验与重叠检查 → 人工科研决定 → 队列内计算与主对象解释 → 可复算发布。

内部按阶段验收，但作为同一套交付管理；每一缺项必须登记对象、缺什么、影响用途、已做检查、所需材料、处理责任类别和下一动作。新的发现允许扩展清单，不锁死为 14 项；旧清单不能悄悄消失。

## 4. A：从 3 项样板扩展为全部研究档案

### 4.1 可核对的检索覆盖

预先登记检索日期、数据库、检索式、字段、分页/导出方式和纳排标准。按三条路径取并集，再去重与逐项筛查：

- GMrepo：官方相关表型完整分页，项目目录/描述关键词与已知 accession 反查；完整 profile 的可取得性另查。项目选择器须先验证实际请求与响应，文档存在不算本次执行成功。
- 原研究：PubMed/Europe PMC、出版社、论文补充资料和作者公开仓库；检索 AD、Alzheimer、MCI、mild cognitive impairment、preclinical、cognitive decline，并按人体肠道/粪便及 16S/shotgun 分层。
- 原始库交叉核对：ENA/SRA/NGDC 的项目、样本、实验、Run 和材料；用于发现 GMrepo 标签遗漏、阶段混用及外部 WGS 候选，不冒充 GMrepo 入库。

检索式不能只用单独的 AD/MCI 缩写；记录歧义和排除。方法是回顾性检索/协调，不宣称预注册或未经达标的系统综述。完成状态按检索路径及日期分别计算，不能用零新增证明全库完整。

公开文件尽量归档，保存请求、原响应、错误、哈希、大小及定位。付费/受控文件只记录合法获取入口与缺项，不绕过限制。获取失败不覆盖已发布有效索引。

### 4.2 逐项补证顺序和检查重点

| 批次 | 项目 | 本批要解决的问题 |
| --- | --- | --- |
| 可用但检验暂缓 | PRJNA554111、PRJNA633959、PRJNA770746 | 原论文/补充表是否能将标本、组别、参与者和重复采样逐条连起来；共享 BioSample、口腔/粪便、实验别名分别核查 |
| 分组/阶段冲突 | PRJEB49329、PRJEB50447、PRJNA611839、PRJNA734525 | AD/MCI/SCD、Aβ 状态等是否有公开个体对应；来源全 AD 标签与原论文分组冲突不能猜解 |
| 原研究或数据缺口 | PRJEB11419、PRJNA1028813、PRJNA489760、PRJNA496408 | 大项目中的真实目标子集、材料、人群、同研究对照、profile/QC 可取得性 |
| 首批样板复查 | PRJEB51982、PRJEB59009、PRJEB77146 | 补充资料和来源一致性、模型协变量与样本范围；既有身份依据与新人工科研复核分开 |

每项档案包括：项目/论文/原研究关系、名称/年份/招募地区与时间、阶段定义、材料、设计、平台/处理方法、原始人数、处理后各分母、编号映射、协变量及缺失、访问/再分发条件、冲突、纳排和用途。

每项至少执行项目原记录、原论文候选关联和补充资料入口核查；不存在、无法访问和不能对应分别记录。找不到参与者表时，仍可完成研究档案，但不能强行开放检验。

## 5. B：主数据语义与身份同步查清

为物种、KO 和 MAG 各固定修订版分别形成数据说明：输入文件及哈希、样本清单、上游工具/参数/数据库版本、值的单位、分母、归一化、零/缺失、分类层级与聚合方式、参与者/重复与分组来源。

优先查本地 manifest、原导出脚本和原始说明，再形成向生信组索取的精确字段表；不得根据矩阵行和、文件扩展名或流程概述猜单位。行和等仅作诊断，不作来源证明。

确认资料后以新修订/显式语义证据登记生效，不回写旧 revision 假装过去已知。即使同为百分比，分类器/数据库、测量对象与组成分母也须另查；秩变换不自动解决这些差异。

本项不阻塞来源档案和属级背景使用，但阻断无依据的主外数值对照；MAG 分类对应不等于 MAG 丰度复现，群落 KO 不等于特定 MAG 的功能归属。

## 6. C：独立性改为关系级、可定位的重叠审查

建立显式关系对象，绑定左右 study/cohort、比较/样本/参与者清单及版本，而非只给项目打“独立”标签：

- 研究关系：同一原研究多 accession、多论文、子队列、后续招募、共享对照或再分析。
- 生物关系：参与者、时间点、标本、实验和 Run；一对多及证据强弱可表示。
- 使用关系：主分析、特征发现/调参、候选筛选、测试或仅文献参考。论文引用或作者相同仅是线索，不自动判重。

先运行精确 ID/别名/文件校验值检查，再查招募地点/时期、作者说明、补充表和数据复用声明；模糊匹配只形成候选关系。跨库不同编号不能证明不重叠；受控/缺失身份不能反推独立。

结果使用“发现重叠”“限定已核范围未发现重叠”“资料不足”，记录覆盖率及尚未检查的层次。不输出无范围的“独立认证”。

验收范围：14 项都做原研究关联和复用线索筛查；当前 5 个分布队列之间 10 对及其与主队列的 5 对均有处理记录。对当前 2 个可检验队列间的 1 对和与主队列的 2 对优先完成深查。新增纳入队列自动扩展关系检查，其他主修订或 MAG 样本集合不同则另建节点，不重复计数。

重复参与者的排除/时间点选择或适用模型须在看结果前写定。无法解决者保持描述性或限定用途，不悄悄按 Run 当独立人扩样本量。主外已知重叠不能作为独立验证，未知关系不能计入独立验证数量。

## 7. D：WGS 真正进入多来源、分层证据体系

### 7.1 来源与层级必须分开

GMrepo 的价值是人肠道微生物组元数据与处理后分类丰度等参考，不是直接提供所有基因、KO、MAG 证据的万能基因库。官方文档列有 Run 完整 species/genus profile API；实际是否可取得仍逐次验证。

| 分支 | 数据来源 | 可以如何展示/计数 |
| --- | --- | --- |
| GMrepo 16S | 当前包及新合格 profile | 属级参考；保留旧图和方法 |
| GMrepo WGS | GMrepo 中实际取得并核验的 shotgun profile | 标明 GMrepo、平台/工具/分类版本、物种或属层级；不将 16S 的 species 标签自动等同 WGS 物种证据 |
| 原研究 WGS | 论文/作者公开处理矩阵及原库关联 | 标明原研究直接接入；不能统计成 GMrepo WGS 接入量 |
| 原始 reads 重处理 | ENA/SRA/NGDC 的原数据 | 独立生信任务；需空间/算力/耗时估算及另行授权，不能在页面迭代里默认启动 |

先查 GMrepo 覆盖，再优先取得可追溯的已处理矩阵；物种分类参考为先，功能矩阵另有来源和语义时再纳入。所有分支共用研究档案、复核、比较、重叠和发布契约，但各有 sourceProvider、platform、featureLevel、clinicalStage 与 processingVersion，不共用旧 322 属检验族或零值规则。

PRJNA798058 是本次查到的真实公开 shotgun 候选：原研究是认知正常人群的临床前 AD 比较，公开了分析代码/处理数据入口。它不是临床 AD/NC 的替代队列；GMrepo 是否收录及本次能取得什么仍未核实。原项目早期描述与正式论文分母存在差异，必须核对实际文件，不能直接导入论文人数。

主队列原论文列有 PRJNA798058 作为其他阶段的公开数据入口。这构成核对“具体分析是否已用过”的理由，但不是实际主矩阵重叠的证明。

### 7.2 接入资格和计算

新 WGS 候选逐项检查人体粪便、shotgun 来源、阶段和同研究对照、矩阵粒度/完整性、零与缺失、参与者及协变量、分类稳定 ID/映射、处理方法和使用条件。完全合格才开放该用途；只剩论文汇总统计时仅展示原研究报告，不重算样本分布。

先选一个按资料可取得性和适用性排列的样板，端到端验证后再批量扩展；不按显著性挑样板。检验族和缺失/过滤/模型规则先写定，产生新方法/数据版本；旧 16S 方法与结果回归保持。16S、不同 WGS 方法和疾病阶段分开展示，不拼接原始丰度、不自动合并 p/q、不制作支持票数总分。

WGS species 匹配到主物种后，只能在获准范围内称物种层参考；要称数值复现仍需可比性及重叠审查。MAG 级一致性需相应序列/基因组匹配、覆盖/定量与方法依据；只有物种 TaxID 不能替代。功能/KO 也不得由物种对应或 16S 推断功能自动推导。

本阶段目标是真实可用的 WGS 参考分支，不预先承诺新增数量。若无合格临床 AD/NC WGS，可如实交付相关阶段参考及临床队列缺口；若仅得检索记录，则此分支数值接入仍未完成。

## 8. E：让人工科研复核成为可执行环节

不新建复杂账号/审核后台。沿用文件登记和 CLI，提供一键生成的待审资料包、标准意见模板、导入校验和报告差异。

审查分开：来源/字段身份、参与者与分组、各模型方法与结果解释、主外可比性、限定关系的重叠、发布可复算性。范围对象必须包含实际比较和左右关系的指纹；旧 scope 字符串可兼容读取，但不能默认为新增双边关系意见。

待审包必须包含关键原文定位、样本/参与者映射、冲突列表、分母与排除流程、协变量缺失/设计检查、完整检验族、负面及不可估计结果、来源/方法/代码/环境版本、复算报告。复核者只需回答具体问题，不必从目录重新找资料。

角色建议为资料整理者、具备生信/统计判断能力的科研复核者、技术发布检查者；记录实际身份与职责，有条件时避免同一人完成所有环节，无法分离须声明。软件不能验证一个名字是否真实，所以材料真实性和人员身份由项目负责确认；不以伪造账户、测试人员、AI 意见代替真实签署。

意见按通过、限用、退回补证、不通过处理；“已看过”不等于同意。导入前展示将改变的用途及统计范围，经显式发布生效；不由表格里填写 confirmed 直接绕过模型/数据门槛。生效、更正、撤销和原件失效要传播到页面、缓存和历史快照的当前用途提示。

科研意见必须覆盖实际方法与解释，不可仅复核哈希。项目尚未指定复核者时，先完成资料、技术和待审包；最终科研签署仍是待交付项，不凭此将目标宣称全部完成。

## 9. F：从读回包推进到实际可复算包

在现有 evaluationId 上增量实现：可重算的最小匿名输入、样本/参与者/分组/协变量清单、完整分类/特征表、比较/方法/审查与关系索引、代码/依赖锁定、运行入口、预期结果/解释、验收报告。不得只打包页面选中的属或筛选后结果。

区分冻结计算材料、来源证明和当前在线用途状态；历史包不因复算而改写。允许权限范围内的矩阵随包，无法分发的依赖给出明确位置、哈希、权限和获取步骤。受试者 ID 仅用研究内匿名标识，不引入直接身份信息。

验收至少覆盖现有两个可检验队列完整 322 属结果、一个描述性暂缓队列、物种 1937 和一个 MAG 对应路径；WGS 分支接入后增加一个真实 WGS 案例。无显著/不可估计结果不能跳过。

在新的临时目录、空应用缓存、不依赖当前服务和主数据库的条件下，从输入重算并比较分母、检验族、效应、区间、p/q、可估计状态和解释。浮点容差按方法事先声明并验证，范围/组别/状态等要求精确一致。先完成可分发参考队列的重算，不承诺当前所有主矩阵都随包离线复算。

输出分别标记：完整可复算、需取得声明依赖后可复算、仅可追溯/读回。仅哈希成功绝不显示“复现通过”。代码和数据使用条件不清楚时不擅自公开归档。

## 10. 页面如何体现，避免再次变成孤立面板

保留主分析实际主题、无侧栏全宽工作区、已有可视化与对象返回上下文。扩展信息组织，不重做一套视觉皮肤。

- 研究目录：显示真实名称、阶段/材料/平台、来源渠道、处理去向与可用用途；原件、审查与重叠详情下钻。
- 菌属/物种检索：支持按实际 featureLevel 选择；未明确对象不默认打开某菌。
- 对象评估：先讲对应层级与能回答的问题，再按临床比较/平台分组展示队列，随后所选队列解释、研究依据及原图；不能将临床前 AD 标题替换成 AD/NC。
- 关系核查：先用可读关系表展示研究/主外关系、核查范围、结论与缺项，不为此新建图谱仪表盘。
- 科研意见：明确谁在何时审查了何种范围，技术检查和科研意见分开；用特定缺项替代到处重复“待核查”。
- 发布与导出：展示冻结版本、当前用途、重算级别与缺失依赖；增加按 evaluationId 读取历史评估的入口，旧记录不混入当前新图。

方法文案、规则摘要和图表标签应消费有效登记/契约，移除会与真实审核/WGS 分支矛盾的固定 pending、16S 和 genus-only 文字。

## 11. 实施依赖与发布验收

| 顺序 | 可并行工作 | 阶段必须交付 |
| --- | --- | --- |
| 1 | A 来源补证 + B 主语义核查 + C 关系契约 | 检索口径、逐研究档案、主数据说明、来源/关系候选和具体缺项；不等待新界面 |
| 2 | C 重叠证据核对 + D WGS 样板 + E 待审包 | 15 对现有关系的处理记录、新来源分支实况、可回答的人工问题、方法/版本设计 |
| 3 | 有效意见导入 + 分层计算/页面 + F 复算工具 | 真正获准的用途、真实结果联动、冻结报告、历史限制与可复算等级 |
| 4 | 全链回归、全清单对账、实际科研签署与发布 | 正式发布说明、范围/限制、科研意见、离线复算报告及剩余依赖责任表 |

技术实现优先复用现有来源、比较、审查、快照服务；补 study/cohort/relationship 与 source/feature 分层，不为档案另造孤立数据库。API、OpenAPI、前端类型与旧链接兼容同步回归；旧参考包和老报告不可覆盖。

最终检查：约定路径是否真的执行；14 项及新增项目有无遗漏；各分母能否逐条追到输入；来源/字段/资格/重叠意见有没有跨用途放行；相同研究是否重复计数；完整检验族是否受界面筛选影响；WGS 是否被误计为 GMrepo；旧数据/版本是否仍可读；新的离线计算能否从输入得到结果；页面和导出是否保持同一评估。

无需现在承诺工期、合格队列数或显著性。出现需作者提供材料、受控权限、付费获取或大规模原始 reads 重处理时，形成明确申请而非自动扩大操作。

## 12. 项目侧最终需要提供什么

1. 实际科研复核人员及职责，能够对生信/统计与研究解释出具真实意见。
2. 主物种/KO/MAG 固定产品的生成说明、单位/归一化及匿名参与者/重复关系；本地已有的先查，不重复索要。
3. 公开渠道穷尽后仍缺失的作者材料/合法访问权限；必要时由项目决定是否联系作者，代理不自行外发消息。
4. 只有已处理数据确实不能满足需求时，再决定原始 WGS 重处理的资源与授权。

这些是取得相应科学用途所需的材料，不是中止其他技术与公开资料工作的理由。最终报告须逐项说明已完成、限用、真实外部依赖，不能把依赖尚缺写成“全部达到预期”。
