# 科学元数据后续实施提醒

## 当前状态

当前物种丰度表和 KO 丰度表没有随数据交付一并声明完整的科学元数据。现有文件尚不能可靠回答以下问题：

- 丰度值的单位和尺度，例如原始计数、估算 reads 数、相对丰度或其他标准化结果；
- 上游标准化、零值处理、伪计数及变换方法；
- 物种和 KO 注释所使用的工具、数据库、版本及关键参数；
- 样本所属研究、批次、受试者、重复测量关系及可用于校正的协变量。

因此，AD-Meta 当前只能安全采用不依赖具体丰度单位的规则，例如 `abundance > 0` 的检出判断。界面和审计信息必须继续标明“上游标准化方式待确认”。在元数据补齐前，不得开放依赖具体单位的任意丰度阈值，也不得把现有组间检验表述为已完成批次、协变量或重复测量校正的确认性推断。

## 后续接入方式

科学元数据应通过版本化的 `Manifest` 和 Artifact 元数据交付，而不是写死在前端、根据文件名猜测，或临时追加到单张图表的 payload。第一版至少应包含：

1. `abundanceScale`、`unit`、`normalizationMethod`、`transformMethod` 和零值处理规则；
2. 物种、KO 及未来 MAG 注释流程的工具、数据库版本、参数摘要和生成时间；
3. `studyId`、`batchId`、`subjectId`、重复测量关系、分组和可用协变量；
4. 产物的 schema 版本、校验和、样本范围及上游 AnalysisRun 标识；
5. 缺失字段的显式状态，禁止使用空值默认为“已确认”。

## 实施顺序

1. 与生信组确认字段语义和可稳定交付的最小集合。
2. 更新 Manifest JSON Schema 与 Artifact Schema。
3. 在导入阶段校验并持久化元数据，校验失败的运行不得发布。
4. 让图表策略从已验证元数据读取单位、过滤条件和推断能力。
5. 补充历史数据迁移或明确标记为 `metadata_unconfirmed`。
6. 完成后更新图表分析策略，并删除界面中的临时“待确认”提示。

## 完成标准

- 任一公开分析结果都能追溯到明确的 AnalysisRun、Artifact 和科学元数据版本；
- 相同 Manifest 和参数能够复现相同的数据准备过程；
- 单位相关阈值只在对应单位经过校验后可用；
- PERMANOVA 等推断明确记录设计矩阵、分层置换和所用协变量；
- 前端展示、审计明细和导出结果使用同一份已验证语义。

该事项属于正式数据接入和确认性统计分析的前置条件。它不阻塞当前探索性可视化运行，但在补齐前，系统必须维持上述科学表述边界。
