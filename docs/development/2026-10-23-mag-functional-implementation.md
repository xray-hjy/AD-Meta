## 页面与交互

沿用 MAG 工作区的玫瑰色主题、浅色页头、紧凑工具栏、可折叠结果区、表格分页与右侧详情抽屉。新增科学图形使用现有 Apache ECharts 模块化适配层；基因区间、专题基因节点和树旁轨道使用 `custom` series。未引入新的绘图库。

## 数据接入与存储

来源为 `backend/storage/raw/ad-nc-mag/PRJCA022804/DRAM2/summary/runs/20261022_233830_828587_1595139/`，共 872 MAG、2,113,311 基因、8 个命名空间及 1,522,600 条非零 MAG–功能关联。

导入器逐一核对 counts/presence，并从基因表独立回算全部 8 类功能计数；同时核对基因总数、联合注释比例、代表 MAG 集合、CheckM2、GTDB 分类和 CoverM 长度。

为支持数百万条基因的索引查询，实际存储采用 **MySQL 模块修订报告 + 不可变、规范化 SQLite 查询库**，没有把全部基因装入模块 JSON，也不在页面请求时重读压缩原表。

- `mag_function_store.py` 导入时建立 `mags/features/counts/genes/hits/distill/info` 表及功能、MAG、基因、contig 索引。
- 文件位于 `backend/storage/derived/mag-functions/<内容 SHA-256>.sqlite`；校验后原子移动。MySQL 模块报告固定相对路径、字节数及 SHA-256，旧发布仍引用旧文件。
- 运行时只读打开；首次访问及文件状态变化后核对哈希，拒绝缺失、损坏或越界路径。
- 沿用 `import:cohort`；`metabolism` 注册为 `dram_summary` 解析器，依赖 abundance、quality、taxonomy，本队列声明为必需模块。
- 无新增 MySQL 表结构迁移；本次实现没有改写 raw、上游脚本或原始 distill。

## 科学口径

1. 功能谱是代表 MAG 的静态注释。样本过滤只改变丰度旁注、候选分布与代理量；低完整度 MAG 的未命中不解释为生物学不存在。
2. 各命名空间独立计数，每个功能内按基因去重，联合注释比例按基因去重，不累加不同数据库命中数。
3. distill 的 1,049 个单 KO 行有差异，原表与报告保留。专题使用已核对计数、明确 KO 或来源目录定义，不把集合覆盖率称为完整通路。
4. ARG passed_0.95 是 passed_0.75 候选子集，保留布尔标记，不相加、不从模型分数重算。BGC 多产品计数之和不等于唯一区域数；未提供与成功零命中不同。
5. DRAM 保留源坐标；antiSMASH region 为原 contig 的 0 起点半开区间。工具间没有经核对的基因对应，不自动拼接。基因汇总不含序列，不提供虚构序列下载。
6. 代理量为 `B(s,f)=Σ A(s,m)·I(C(m,f)>0)`、`W(s,f)=Σ A(s,m)·C(m,f)`，A 沿用 CoverM 百分比，不代表群落 KO 丰度、表达量、代谢通量或产物量。统计以样本为单位，不把 MAG 当作 AD/NC 受试者。
7. 群落 KO 仅按功能 ID 对照，不建立未经核对的 MAG→物种映射。输出用于研究线索，不扩大为临床诊断、已验证生物标志物或因果结论。
