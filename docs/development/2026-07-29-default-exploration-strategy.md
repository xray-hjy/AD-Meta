# 2026-07-29 默认探索策略与投影缓存更新

## 背景

阶段二引入分析范围和图表专属参数后，页面存在两个体验问题：

1. 首次进入图表时经常等待后端重新计算，缺少稳定的默认视图。
2. 在一张图中选择 AD 组、自定义子集或其他参数后，切换图表会把同一条件直接套到下一张图。

本次更新建立“默认探索方案 v1”。它只定义进入图表时的可复现起点，不代表唯一正确的科研参数，也不替代完整结果和明细数据。

## 状态隔离

- 图表状态按 `analysisRun + datasetRevision + chartKey` 保存到浏览器会话存储。
- 每张图独立保存分析范围、Top N 和该图专属参数。
- 第一次进入图表使用注册表默认值；返回已访问图表时恢复该图在当前会话中的最后状态。
- 切换分析运行或数据修订版后使用新的状态命名空间，避免不同分析结果互相污染。
- URL 仍保存当前图表的有效状态，便于刷新和复现当前视图。

## 缓存与加载

### 前端

- React Query 的投影结果保鲜时间调整为 15 分钟，内存回收时间为 1 小时。
- 侧栏悬停图表时会按该图的独立状态预取；未访问过的图表预取默认投影。
- 自定义范围或参数仍按需请求，加载状态只表示该次投影正在计算或读取。

### 后端

- 图表投影除进程内 LRU 外，增加 MySQL 模式下的磁盘持久缓存。
- 缓存键包含分析运行、Artifact、数据修订版、投影类型、分析范围、Top N、科学参数、计算版本和缓存结构版本。
- 参数、数据修订版或 `COMPUTE_VERSION` 变化时自动生成新缓存，不会复用旧计算结果。
- 缓存使用临时文件加原子替换写入，目录为 `backend/storage/cache/projections/charts/`。
- 新增 `python -m app.cli.warm_projection_cache`，用于部署或数据导入后预热所有已发布 Artifact 的默认投影。

## 边界与后续

- 缓存只减少重复计算，不改变完整分析结果，也不扩大或缩小图表本身的筛选规则。
- Top N、长尾聚合和显著性筛选仍须通过图表投影说明向用户披露。
- 论文级导出、完整明细分页和更复杂的用户自定义筛选继续沿用“完整结果、交互投影、明细数据”三层契约推进。
