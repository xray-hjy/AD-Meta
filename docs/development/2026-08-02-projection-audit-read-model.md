# 2026-08-02 投影审计读模型

## 目标

“查看筛选与合并明细”需要回答某个可视化投影为什么展示、合并或排除一项数据。它是分析结果的可追溯解释，不是临时 UI 缓存，也不是第二套科学数据源。

本次将该能力建设为正式的版本化派生 Artifact：完整分析结果仍由 `AnalysisRun` 与源 `Artifact` 管理；图表投影负责浏览器展示；投影审计读模型只保存该投影的逐项决策和来源信息。

## 身份与生命周期

一份审计产物由以下字段共同确定：

- 源 `Artifact`；
- 源数据修订号；
- 当前 `projectionKey`；
- 图表类型与审计栏目；
- 后端计算版本；
- 审计结构版本。

样本范围、Top N、统计参数、源修订或计算版本发生变化时，都会产生新的投影身份。旧产物不会被当作新结果复用。审计产物保存状态、行数、SHA-256、生成时间和来源元数据，可随源 Artifact 删除或通过仓储接口显式失效。

## 分层职责

| 层 | 职责 |
| --- | --- |
| 科学计算服务 | 按每类图表的规则生成展示、合并、过滤和布局决策行 |
| 审计仓储 | 持久化审计 Artifact 与行，提供索引筛选、选项查询、排序和分页 |
| API | 校验投影身份，分别提供元数据、筛选选项和分页行 |
| 前端 | 先显示元数据与当前页，用户打开某个筛选框后才查询其选项 |

科学规则不放入 SQL 仓储，存储实现也不进入图表组件。未来数据量需要采用 Parquet/DuckDB 或独立分析库时，可在仓储边界后替换，不改变图表策略与前端契约。

## 查询契约

- `metadata`：栏目、列定义、样本范围、投影摘要和来源信息。
- `options/{field}`：特征、样本、处理结果或原因的可搜索候选项。
- `rows`：当前筛选、排序与分页下的明细行。

常用的特征、处理结果、原因及默认顺序由 SQL 索引查询。样本存在性筛选和尚未结构化的数值列排序暂由服务层兼容处理；若这些路径成为高频大数据查询，应通过新的审计结构版本增加专用列，而不是继续扩大 JSON 内存扫描。

## 构建策略

默认图表投影及其审计 Artifact 由以下命令预热：

```powershell
cd G:\admeta\backend
.\.venv\Scripts\python.exe -m app.cli.warm_projection_cache
```

预热可以重复运行：已有且身份一致的 `ready` 产物直接复用。API 保留缺失时的幂等构建作为开发环境和异常恢复手段，因此缓存目录是否随仓库分发不会影响正确性。

## 一致性原则

1. 源分析结果是唯一事实来源，审计读模型只能由已校验的投影重建。
2. 前端请求必须携带正在显示的 `projectionKey`，参数已变化时拒绝返回旧明细。
3. 任何合并、过滤和 Top N 规则由图表策略定义，仓储层不得自行解释科学含义。
4. 性能优化只改变构建和读取方式，不改变审计行、汇总数和图表结果。
5. 默认预热负责常用路径，用户自定义范围按身份生成并可复用，不预先穷举组合。
