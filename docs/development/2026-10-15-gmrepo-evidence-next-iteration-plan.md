# GMrepo 外部证据评估后续迭代方案

日期：2026-10-15。版本：1.1（增量设计）。状态：用户已确认执行；迭代一的研究台账、统一资格和页面/报告贯通已实施，来源补齐、科研复核及后续迭代未全部完成。当前进展见[迭代一实施记录](2026-10-15-gmrepo-research-ledger-implementation.md)。运行包、统计方法及既有科研审查结果未改写。

本方案接续[首版设计](2026-10-14-gmrepo-evidence-workspace-design.md)、[实施记录](2026-10-14-gmrepo-evaluation-implementation.md)、[前端整理](2026-10-15-gmrepo-ui-refinement.md)与[SOP](2026-10-14-gmrepo-evidence-sop.md)。原有边界继续生效；历史设计的“未实施”与旧待办不能替代当前代码和真实记录。

迭代一之后的执行细化见[迭代二方案 v1.2](2026-10-15-gmrepo-evidence-iteration-two-plan.md)及[迭代二实施记录](2026-10-15-gmrepo-iteration-two-implementation.md)：研究内容补齐、有效复核、对象解释和固定评估交付已开展。本总体方案保留，不代表剩余来源和科研工作已经完成。

## 1. 本轮目标和停止条件

近期交付目标：**具备研究台账、分用途资格判断、对象级解释和复核发布记录的正式外部参考评估模块**。

用户应能回答：

1. 这项研究为何在目录中，使用了什么人群、材料、平台和比较？
2. 当前对象对应到哪个外部分类层级，有哪些可用观察？
3. 哪些研究不能检验或不能比较，具体缺什么依据？
4. 结果来自哪些文件、规则、样本范围和复核记录，能否重新核查？

达到上述目标即可交付当前用途。**不以扩大可检验队列数、得到显著结果、找到 WGS 或完成全部外部验证为验收目标。**

分开三种用途：

- 外部参考：当前优先交付，允许描述性结果与队列内探索性检验，逐项标明资格。
- 数值对照与独立复现：条件核实后分别开放；能比较观察结果，不等于证明独立复现。
- 模型外部验证：需要另行交付真实冻结模型、兼容特征和独立评估设计，不纳入近期版本的完成条件。

## 2. 已有基础：保留，不重复建设

基线为当前固定运行包与清点记录：13 个接入项目、1269 Run、800 完整 profile、322 属；5 个可展示分布的队列、2 个通过当前队列内检验资格的队列。Run 不等于独立参与者。

已核对 AD 标准表型的 13 个项目均在本地；与认知障碍表型并集为 14 项，新增 PRJEB77146 仍属发现但未接入。未完成的关键词、阶段与 WGS 范围不能据此写成已完成。

保留无侧栏工作区、统一主分析主题、研究目录/菌属检索/质量/方法视图、原图表与样本表、固定版本、物种/MAG 入口和跨页上下文、JSON/Markdown 导出。最近相关回归为 74 项，真实浏览器验收 13 个场景；这仅证明技术行为，不是科研复核。

不重做一套后台或数据版本体系，不给所有主分析对象预先贴 AI 候选标签，不用更多装饰页面替代证据建设。

## 3. 工作分解与依赖

| 工作包 | 交付重点 | 依赖 | 放行条件 |
| --- | --- | --- | --- |
| A 研究台账与统一状态 | 项目/原研究/比较集合、来源、字段核查、缺项、统一能力状态 | 当前包与发现清单 | 每个指定范围内项目有记录；状态可追溯、跨接口一致 |
| B 来源清点与材料补齐 | 同研究对照、阶段、材料、关键词/WGS、旧原件回执 | 先冻结检索/纳排口径；与 A 并行 | 每项发现有处理去向；获取失败与未完成范围有记录 |
| C 对象解释与研究核查展示 | 对象级事实、结果、限制、依据和下一步，资源页呈现缺项 | A 的结构化状态；B 可逐批补充 | 任一解释可追到输入与规则，缺资格不产生结论 |
| D 科研复核与版本交付 | 复核记录、冻结清单、真实案例、读回/重算核对 | A/C；B 的实际完成范围明确 | 人工复核、自动校验分开；发布声明与实际能力一致 |
| E 数值对照及新平台能力 | 主矩阵语义、分类统一、重叠核查、可比结果；WGS 按就绪度接入 | 相关数据与方法条件通过 | 按用途独立放行；不替换或升级未满足条件的参考结论 |

执行关系：**先 A；B 在规则固定后并行；A → C → D 构成近期交付；E 按条件单独推进。**

不等待未知外部材料才能开发台账与缺项展示，也不因为前端完成就宣布 B/D/E 已完成。

## 4. 迭代一：把研究台账和状态做实（A + B 的启动）

### 4.1 建立研究级、比较级的结构化登记

复用现有 discovery、分组规则、身份审查与发布 manifest；新增的是它们之间的明确引用，不再复制一份互相矛盾的“事实表”。

建议概念对象：

- StudyRecord：原研究标识、相关项目 accession、论文及作者公开资料。尚不能确定同一原研究时，studyId 保持待核查，不把每个项目自动当作独立研究。
- ComparisonRecord：研究内 AD/NC、MCI、风险或临床前阶段的明确定义及样本集合，记录材料、时间点、配对/纵向关系。
- ReviewRecord：审核字段/用途、输入 fingerprint、依据文件及定位、结论、执行/复核者、日期、版本和撤销/更正记录。
- AcquisitionRecord：原文件地址、请求范围、获取时间、大小、哈希、归档位置和实际可读取状态。

每个关键字段同时保留原值、标准化值、来源和核查状态。论文简称、年份、人群/国家、样本材料和平台能核实才展示；不从项目描述猜定，不用虚构名称丰富页面。

首批对象是 13 个已接入项目及已发现的额外 1 项；“台账覆盖”不等于“数据接入覆盖”或“研究已全部核查”。

### 4.2 统一资格和缺项计算

同一评估服务向 `/resources`、`/audit`、`/evidence-summary`、`/report` 提供一致的实际状态。协议中的计划范围与运行时已完成范围分开；修正目前 `pending_live_inventory` 与实际 partial 清点记录并存的问题。

状态维度分开：元数据、profile、描述性分布、未调整检验、调整检验、分类对应、主外可比性、研究独立性、科研复核。不得合成“证据可信度 85 分”或一条自动升级等级。

缺项改为结构化记录，至少包括：reasonCode、具体对象/样本范围、缺少的依据、影响的能力、核查动作、当前处理状态及来源。已有中文理由继续作为可读解释，不能仅改标签而没有实际记录。

已有 2 个队列的有效身份审查按其审核范围保留；新抓取的未核查元数据不能覆盖旧的有效专项审查。发现冲突则并列依据并复核。撤销、更正或证据文件不匹配须使依赖结果失效，包括缓存。

### 4.3 来源工作同步启动，但不假定能全部补齐

冻结本轮 AD/MCI/风险/临床前、人体肠道材料、同研究 NC、16S/WGS 的检索范围和纳排口径。既有结果已知，回顾性整理须如实标明，不能写成分析前预注册。

核对现有 13 项的原研究、同研究对照、材料与阶段；对新增认知障碍项目单独审查，不直接改名为临床 AD。继续核实官方关键词/项目选择器请求契约，无法使用时记录阻碍并选择可取得的官方导出，不能将服务返回 1002 当成无相关研究。

获取原件保留回执；发现清单、研究去重、纳入、未取得、待审查和排除理由可对账。新资料不覆盖旧固定处理包；数据或处理变化另发版本。没有新 WGS 时也要交付清点范围和获取结果，而非空白待办。

### 4.4 本轮验收

- 指定范围内每个项目均有可读记录，关键未知字段明确标注，不能将“已登记”写成“已复核”。
- 对任一队列，页面、接口和报告的资格、理由、单位和分母一致。
- 至少覆盖可描述、可检验、无 AD/NC 子集、缺 profile、旧证据失效与分类不对应等测试路径。
- 保持当前统计方法和完整 322 属检验族；搜索、分页、可用性筛选不改变 q 值。
- 科研人员尚未复核的记录保持 pending；不得由自动测试填入虚构审核人或通过结论。

## 5. 迭代二：让研究对象得到清楚、可追溯的解释（C + D）

### 5.1 对象页回答四个问题

在现有全宽页面上整理表达，不再换一套布局：

1. 对应关系：主物种/MAG、固定版本、参考属、映射依据及层级。
2. 实际观察：哪些队列有数据，未调整/调整结果及其不同样本人数，来源 marker 单列。
3. 可解释范围：能说属级背景、能做何种比较；哪些方向冲突、未获 FDR 支持或根本无法评价。
4. 待核查事项：针对这个对象的阻断项、影响与可采取的核查动作，直接关联研究与来源。

新增解释仍从结构化证据和版本化规则生成，不用自由生成 AI 填充研究结论。来源 LDA、模型、样本行与研究分别计数；不挑显著研究，不把未获支持写成反证。

资源行展示真实研究身份和“缺什么—影响什么—如何核查”；对象页展示其相关事项。它们读取同一台账，不各写一段无法对账的说明。原分布图、统计和样本查询继续作为下钻依据。

### 5.2 建立最小复核发布包

复用现有 release/revision 能力，绑定：输入快照和清单、研究/比较登记、核查版本、规则/方法/代码版本、结果、复核记录、变化说明和真实对象报告。运行包与重处理归档分别标明可用性。

用真实数据交付至少三类案例：物种关联属级背景、MAG 可靠对应或缺路径、队列因资格不足暂缓。方向冲突或未获支持案例按实际结果和公开选取规则组织，不保证存在显著支持案例。

审核需要三个职责：资料整理、科研方法与解释复核、技术发布；可由项目成员分工，当前不指定不存在的人员。审核记录允许不通过、待补和修订，不能只记录批准。

### 5.3 近期版本的完成判据

每条对外解释能够追到主/参考对象、样本集合、来源文件、规则和复核状态；用户能区分事实、计算结果、解释和未知项。13 项与额外发现项的去向可核对，检索未完成范围可见。

技术路径、导出与重新读取通过测试，科研核查由有相应能力的成员留记录。无法复核的部分不放行相应用途，但不阻止发布边界清楚的可用参考功能。

达到这里，可按实际完成范围发布“正式外部参考评估模块”；仍不可称独立外部验证平台。赛事呈现另需对齐具体评分标准，不承诺评审通过。

## 6. 迭代三：按条件解锁数值对照与更广来源（E）

先交付主数据可比性核查报告，再决定做什么计算：

- 主物种矩阵：实际输入文件、成功生成记录、丰度单位、标准化/分母、零与缺失、分类版本、样本与参与者关系、分组与协变量。
- 分类：物种到属的归属是否唯一、可否聚合、旧名与未解析的处理；MAG 分类关联不等于其丰度与读段矩阵具有可替换性。
- 研究关系：项目与原研究关联、重复样本/参与者、主外及外部研究间可能复用。没有相同 Run 不足以认定完全独立。
- 方法：明确比较对象、样本集合、处理方案及解释权限，科研方法审核后冻结新版本。不直接把原物种效应与外部属效应相减，也不拼接丰度矩阵或复用一条共同丰度轴。

分开两道门：可比性通过才开放相应数值对照；独立性另经审查，才允许讨论独立复现。已知重叠的数据可以如实展示观察，但不计作独立验证。即使得到属级方向对照，仍不能升级成某个物种/MAG/功能已验证。

WGS 一旦发现可取得的数据，从原件、材料、人群、分类与方法审查开始走同一链路；不强行套现有 16S 方法。KO/AMP 需真实归属链；模型验证需真实冻结模型及未参与开发的评估数据。这些作为条件化扩展，不用占位图或演示结果冒充完成。

## 7. 开发切入点与保护范围

| 区域 | 主要改动 | 必须保护 |
| --- | --- | --- |
| metadata / 发现与审查登记 | 研究/比较/字段来源的补充记录和校验 | 旧运行包、原件与旧审查可恢复；未知不覆盖已核实值 |
| gmrepo_evaluation_service / analysis_service | 统一状态、结构化 blockers、对象解释及缓存依赖 | 原有资格审查、固定 FDR、来源与重算分离 |
| gmrepo_models / API / 前端生成类型 | 对新增对象明确 schema，兼容扩展现有资源和报告接口 | 不改变既有字段含义；破坏性变更须升级 schema 并兼容旧链接 |
| ReferenceRegistry / SubjectContext / FeatureEvidencePage | 真实研究身份、用途资格、对象解释、依据下钻 | 统一主题、无侧栏、现有图表、跨页对象和固定版本 |
| CLI / 导出 / 验收 | 台账校验、来源清点、发布包及真实案例 | 网页请求不触发源库下载；新版本不静默替换旧版 |

首轮具体开发顺序：列出当前状态来源和冲突 → 定义并校验登记 schema → 迁移现有事实且保留未知项 → 统一能力/理由服务 → API 与报告 → 现有页面呈现 → 回归与真实案例核查。

不在近期范围：管理员审核后台、复杂任务分派、用户账号权限扩建、候选批量评分、荟萃分析、临床预测。后续真实模型候选交付后再决定是否增加批量关联，不能将其反推为当前必备能力。

## 8. 需要项目侧提供的内容

业务开发可从当前代码和记录开始，不必等待全部外部资料。科学放行则需要：

- 实际资料整理和科研复核人员及其职责范围；未指定时保持待复核。
- 主矩阵和外部队列的缺失原件、可定位的生成/审查依据；没有资料时不得凭界面补写。
- 如需用于某项竞赛，提供其真实评审标准与交付期限，另行安排材料优先级。

不预填完成日期、获取成功率、用户效率或科研结论。后续每轮按交付物和门槛验收，延期或阻断项必须落到具体依据，不以“页面完成”代替科学完成。
