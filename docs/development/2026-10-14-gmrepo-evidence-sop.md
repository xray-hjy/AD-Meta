## 1. 用途与规范依据

本项目是面向 AD 脑肠轴研究的研发辅助工具。GMrepo 作为外部数据来源，辅助候选分类特征解释和研究优先顺序判断。项目贡献包括针对研究场景的筛选、样本与疾病阶段核查、分类对应、证据组织及可追溯交付，第三方数据归属于原数据库和研究。

规范参考：

- [STORMS](https://pmc.ncbi.nlm.nih.gov/articles/PMC9105086/) 是人类微生物组研究报告指南。借鉴其研究设计、参与者、测序和处理、混杂、统计、数据与代码报告要求，逐项登记适用性及缺项。
- [PRISMA 2020](https://pmc.ncbi.nlm.nih.gov/articles/8007028/) 是系统综述报告指南。借鉴其可追溯检索、预先规定的纳排、筛选及排除理由报告方式；本项目的 GMrepo 数据接入本身不是完整系统综述或荟萃分析，不据此声明全面符合 PRISMA。
- [GMrepo v3 官方论文](https://academic.oup.com/nar/article/54/D1/D734/8340991) 说明数据库定位和可下载的数据类型；实际获取能力以查询时的官方接口/文件为准。

以上属于报告规范参考，不是统计方法有效性认证，不保证项目竞赛评分。针对本项目的阈值、适用方法和解释权限，由预先版本化的方法方案与实际数据条件决定。

## 2. 发布前区分三种证据用途

| 用途 | 开放前提 | 对外说明 |
| --- | --- | --- |
| 外部参考 | 来源可追溯，对象及分类层级清楚；描述性与检验资格分别核查 | 16S 属级背景、单队列探索性结果或来源记录 |
| 跨队列数值复现 | 同层级分类及分析目标可比，单位与方法明确，样本身份和主外重叠审查通过 | 在某个明确定义的比较中观察到同向/不一致结果，说明不确定性 |
| AI 模型外部验证 | 真实模型交付，训练/调参和外部评估队列分离，特征转换可执行，模型及评估规则先冻结 | 固定模型在独立评估数据上的真实性能，含人数、区间和限制 |

16S 属级背景不能直接评估物种/KO/AMP 多模态模型。WGS 存在也不自动保证输入特征齐全或处理口径兼容。如果外部数据用于候选选择、调参或模型先验，就不能同时把它当作未参与开发的最终验证集；须单独划分或设计新的独立评估。

当前主要处于第一种用途；现有主物种服务把数值对照标记为待核查。当前 5 个队列可展示 AD/NC 分布，只有 2 个通过独立参与者核查并开放现有探索性检验。

## 3. 标准流程与通过条件

```text
研究问题与规则冻结
  → 系统检索与范围清点
  → 原件获取与来源留存
  → 研究/样本/分组核查
  → 分类与数据语义标准化
  → 队列内计算与结果复核
  → 主外对应和证据解释
  → 可复核发布、案例演示及版本更新
```

每个节点产生机器可读记录和可读说明。节点状态为未开始、执行中、已通过、部分可用或待补证据；不能因为后续界面能展示，就自动把前面步骤标成通过。

| 步骤 | 必须执行 | 产物 | 通过条件及失败处理 |
| --- | --- | --- | --- |
| S0 研究问题与规则 | 明确 GMrepo 检索范围、人体肠道样本、AD/NC 比较、阶段分层、平台、对象层级、方法与纳排 | protocol：规则版本、日期、执行/复核角色、变更记录 | 分析结果揭示前记录规则；旧快照回顾性整理如实标明；不能看显著性再选研究 |
| S1 范围清点 | AD 标准表型与名称/研究设计交叉检索，补同研究 NC；核实完整分页；与当前 13 项比对 | search log、去重研究/项目目录、逐项筛选记录 | 查询时间/参数/分页有凭证，发现数可核对；检索受阻则注明未完成，不声明完整覆盖 |
| S2 获取与封存 | 元数据、可用 profile、marker、原研究及身份资料；核实 16S/WGS | 原文件、获取回执、URL、字节数和哈希、文件可用性 | 原件/派生结果分开，错误和缺文件有记录；哈希不能替代真实性或上游流程核查 |
| S3 样本与设计审查 | 疾病定义、阶段、材料、参与者、重复测序/采样、配对、年龄性别及可用药物/BMI等 | study/sample registry、分组依据、重复与重叠登记、协变量缺失表 | 每种用途有明确样本集合；缺独立参与者证据只描述；配对/纵向设计不能套独立两组方法 |
| S4 标准化 | 平台、分类体系/release、稳定 ID/核对旧名、单位、分母、零与缺失、待解析比例 | mapping audit、数据契约、样本×特征/长表、质量报告 | 主键和单位明确、profile 比例可核对；未解析保持未解析，平台冲突查原研究；不能无记录重新归一化 |
| S5 统计与复核 | 固定比较和检验族，计算方向/效应/区间/p/q；调整资格、模型诊断和样本变化说明 | 方法版本、完整结果、排除记录、运行环境与复核记录 | 按实际数据采用方法；无原始计数不能伪装计数模型；条件不足不输出虚构 p/q；搜索不改变 FDR |
| S6 对应与解释 | 主对象固定版本解析，平台/层级/研究独立性审查，分开来源 LDA与重算；规则摘要 | 对象关联、证据记录、句子依据、缺项、规则版本 | 同一研究只计一次；属背景不升级为物种/功能证明；主外不可比不下复现结论 |
| S7 发布与复核 | 新目录校验、版本绑定、旧版保留、导出、案例复核及流程计数对账 | release manifest、复核报告、可读报告、变化说明 | 能从某条证据回到输入/规则/结果；异常不静默替换；关键科研核查没有完成复核时标明待复核 |

S0 的纳排应按用途分别制定。资源目录可以保留无对照的 AD 研究，队列内 AD/NC 比较必须有可信配套对照；不能拼接无关研究健康人造一个对照组。发现范围覆盖 16S/WGS，MCI/风险/临床前独立分层，口腔等其他材料不计入肠道参考集合。

各计数单位分别保留：检索记录、论文/报告、项目 accession、原研究、Run、标本和独立参与者。筛选流向可使用互斥的主要排除理由进行总数对账，附加问题另列标签。未来覆盖率的分母是指定日期和范围内已核实发现的目录，而非 GMrepo 全库或网页首屏数量。

## 4. 当前方法冻结与扩展规则

现有 16S 处理包的探索性方法先保留，记录其适用边界。现有代码采用队列内独立两组 Mann–Whitney U、秩二列相关、所选属的固定种子 bootstrap，以及完整协变量子集上的秩响应 OLS/HC3。当前两种模型分别对完整 322 属做 BH 校正，模型有资格/设计诊断条件。

这不是通用的微生物组正式分析金标准。说明组成约束、未测饮食/用药等混杂，及调整前后样本集合差异。报告指南不能证明当前统计方法没有偏差。新平台、原始计数或配对/纵向研究加入后，需要另行制定方法版本和验证条件，不能直接套用现有 16S 方法。

任何影响结果的调整须保存：原因、变更前后规则、输入版本、影响队列/特征和敏感性结果。预先规定的主分析与发现结果后增加的探索分析分开标注。显著、非显著、方向冲突和无法估计都保留。

比较图按效应单位分开；来源 LDA、秩二列相关和调整后的百分位秩点差不得相加。多研究方向总结还需研究去重和独立性审查，统计意义上的合并效应/异质性是后续单独方法任务。

## 5. 最小可复核交付包

以下是未来交付要求，不代表目录已经生成：

```text
protocol                    检索、纳排、比较及方法规则
search-log                  源库查询日期、参数、分页与回执
study-registry              项目、原研究、平台、疾病阶段、获取状态
selection-log               逐项纳入/排除及依据
sample-review               分组、身份、重复、协变量与重叠核查
mapping-audit               源/目标分类体系、层级、依据与未解析项
input-manifest              原件位置、获取凭证与文件哈希
analysis-manifest           输入、方法/软件版本、脚本、参数和结果
evidence-records            证据对象、摘要规则、引用与缺项
release-review              对账、读回/重算检查、科研复核与变化说明
case-reports                真实对象的端到端证据报告
```

使用现有 manifest/revision/AnalysisRun/Artifact 能力建立引用关系，避免创建重复的数据集体系。运行交付包与完整科研归档分别登记：给用户的运行包可以精简，重处理所需的输入和脚本必须有实际可定位的归档。旧 2026-10-09-v1 原文件保持不变，补充记录独立绑定其 fingerprint。

复核由采集整理、科研方法、平台发布三个角色承担；具体人员当前未指定，不能填写不存在的审核人。关键疾病分组、参与者关系、分类映射和解释由具备相关知识的成员复核并留记录。自动校验与人工核查分别报告；仅有自动测试不视为科研复核已完成。

## 6. 对评审可展示的真实材料

| 材料 | 回答的问题 | 必须避免的错误 |
| --- | --- | --- |
| 一页流程图与规则摘要 | 接入步骤如何重复执行，各阶段怎么放行？ | SOP 草案写成已完成流程或国际认证 |
| AD 相关范围与筛选报告 | 为什么纳入这些研究，还有哪些缺项？ | 当前 13 项充当 GMrepo 全部 AD 范围 |
| 研究质量与独立性报告 | 样本关系、疾病分组和混杂核查到哪一步？ | Run 当人数、多个结果重复当队列 |
| 真实端到端案例 | 主对象如何关联外部背景，结论能到哪层？ | 示意数据冒充实际发现、仅展示支持结果 |
| 版本与复核记录 | 结果能否找回输入、复核和重算？ | 哈希一致等同全流程或科学结论认证 |
| 使用效果记录 | 与人工切换数据库相比节省了哪些步骤？ | 未测量就填节省时间、准确率或用户满意度 |

案例至少覆盖可解释的外部结果和因缺项暂缓的路径；同向、冲突、未获支持案例依实际结果选取并说明选取规则，不保证数据库一定存在某类示例。主数值对照暂未通过时，演示真实的属级背景关联与缺项处理，不能把页面链接包装为独立验证。

使用效果可安排相同对象/任务下的人工查找与平台流程比较，记录查找步骤、耗时、来源遗漏和解释错误，明确执行人数及任务数量。报告实际小规模试用结果，不外推临床准确性或普遍效率。
