# 2026-10-14 网站启动与首屏优化方案

状态：已实施 Vite 范围配置、启动状态与异常恢复、后端按需导入、构建/预览入口及兼容运行环境路径解析。运行环境实体迁移仍作为后续独立维护步骤。

目标：缩短本地启动后打开首页的等待时间，让加载进度和失败状态可见，并减少后端启动时不必要的模块加载。

## 1. 当前证据与判断

本次调查使用本地源码、现有数据及隔离的 Vite 服务。最终对照使用启动脚本选择的 Node 22.23.3；前端使用 Vite 6。所有性能数字是这台机器上的调查结果，不是跨机器承诺。

| 观察项 | 结果 | 含义 |
| --- | --- | --- |
| `frontend/.tmp` 文件规模 | 约 70,431 个文件 | 前端根目录包含完整 Node/R 运行环境与相关库 |
| 原文件监听范围，仅显式指定入口 | 导航 45 秒超时；此时监听约 5,149 个运行环境目录 | 显式入口单独使用不能解决监听开销 |
| 排除 `.tmp`、`coverage`、`output`，保留默认入口规则 | 一轮冷加载约 24.1 秒，随后约 0.24 秒 | 排除监听目录有效，但仍需收敛入口规则 |
| 排除上述目录，同时指定 `index.html` 入口 | 同一批次约 1.9 秒，随后约 0.23 秒；较早独立测试约 2.5 秒 | 两项组合是当前优先实施的优化 |
| 首页请求后端 API | 0 次 | 首屏渲染不需要等待 GMrepo 接口 |
| GMrepo 包完整校验 | 约 44 毫秒 | 当前不构成白屏的主要瓶颈 |
| GMrepo 数据加载 | 首次约 79 毫秒，缓存命中约 1 毫秒 | 数据缓存工作正常 |
| 后端准备模块导入 / API 模块导入 | 一轮测量约 4.8 秒 / 7.3 秒 | 有独立优化空间，需进一步分阶段计时 |

两项前端配置的组合收益已观察到。不同轮次仍存在文件系统缓存、系统负载影响，应以交错重复测量复核收益；不能将全部差异精确归因于单项配置。

纠正早期扫描假设：按当前 Vite 默认依赖扫描规则实测得到的 HTML 入口只有 `frontend/index.html`。R 帮助文档未被证实作为依赖入口；已直接观察到的是对运行环境目录的大量文件监听。

用户当前采用两个终端分别运行 `Start-ADMeta.ps1 backend` 和 `frontend`。根脚本的前端命令直接启动 Vite，不等待后端健康检查；`npm run dev` 的联合启动路径才包含 `wait-on`。验收应覆盖这两种入口。

## 2. 第一阶段：收敛文件处理范围

修改 `frontend/vite.config.js`，新增以下配置，并合并到现有对象中：

```js
optimizeDeps: {
  entries: ['index.html'],
},
server: {
  // 保留现有 host、port、proxy
  watch: {
    ignored: ['**/.tmp/**', '**/coverage/**', '**/output/**'],
  },
},
```

显式入口使用精确路径，避免全目录入口查找。文件监听继续覆盖 `src`、`public`、配置文件和正常开发资源，排除与页面开发无关的临时运行环境和报告。

保留已有依赖预构建缓存以及 Vite 自身的默认忽略项。Git 的忽略配置不能替代 Vite 的监听配置。原图表计算缓存、GMrepo 数据及发布数据版本不参与这次调整。

本阶段暂不增加全站预热或长依赖清单。若仍有瓶颈，先看模块转换日志和请求瀑布，再选择少量高频入口预热。

验收：首页能打开；修改 JSX/CSS 后热更新有效；直接进入 GMrepo、分析工作区正常；`/api` 代理有效；监听目录中不出现 `.tmp/runtime` 的子目录。

## 3. 第二阶段：让加载和失败状态可见

修改 `frontend/index.html` 和入口初始化代码，增加轻量的启动状态管理。

| 状态 | 页面行为 | 触发条件 |
| --- | --- | --- |
| HTML 已返回，应用尚未挂载 | 显示品牌、简短加载提示 | HTML 中直接提供文字与小段样式 |
| 加载等待超过 15 秒 | 显示“加载时间较长”和手动刷新入口 | 仍未收到首次应用提交标记 |
| 启动资源明确加载失败 | 显示加载失败与重试入口 | 捕获入口脚本及其启动依赖加载失败 |
| React 首次提交 | React 接管页面，结束启动计时与监听 | 提交后的 effect 发出就绪标记 |
| React 渲染发生异常 | 显示可恢复的错误界面 | 顶层 ErrorBoundary 捕获组件渲染异常 |

启动提示不依赖 React、组件库、远程字体或后端接口。超时提示表示等待较长，不把仍可能完成的加载误判为失败。

React 首次渲染会替换 root 中的初始内容。就绪标记应由提交后的 effect 触发，而不是紧跟 `root.render()` 调用；计时器和监听要支持 StrictMode、热更新以及重复清理。React 接管后的组件异常交给 ErrorBoundary，启动资源错误与渲染错误分别处理。

加载提示只改善等待体验，不能代替第一阶段的实际性能修复。首页动画单独计时；当前入场动画有 6 秒兜底，其完成时间不能作为脚本白屏耗时。

验收：对脚本请求人为增加延迟时能看到提示；阻断启动脚本时能看到失败状态；恢复后可刷新进入；正常启动后提示、计时器和事件监听都结束；后端未启动时首页仍可显示。

## 4. 第三阶段：减少后端无关模块导入

### 4.1 让已有数据库的准备路径保持轻量

当前 `prepare_runtime.py` 顶层导入 `bootstrap_storage`，后者又顶层导入 `import_dataset`，进而引入预计算等模块。数据库已有发布数据时只需要同步分析登记，这些导入仍会发生。

设计：

- 将 `DEFAULT_MANIFEST` 等路径常量提取到轻量的共享模块，供准备、bootstrap 和同步命令使用。
- 在需要首次 bootstrap 的分支中加载导入与预计算模块；也可在 `bootstrap_storage()` 内延迟加载 `import_dataset`，结合导入计时选择最小改动。
- 已有数据库仍同步分析登记；空数据库仍执行现有初始化流程；原有失败行为继续向调用方传播。
- 调整相关测试的 mock 位置，并增加“已有数据路径不导入预计算模块”的真实子进程检查，验证减少的是导入而不只是函数调用。

涉及：`backend/app/cli/prepare_runtime.py`、`bootstrap_storage.py`、`sync_analysis_manifest.py`、轻量路径模块和相关测试。

### 4.2 按需加载 GMrepo 推断模块

当前 `app/api/gmrepo.py` 顶层加载 `gmrepo_analysis_service`，后者包含 SciPy、statsmodels 等依赖。将分析服务的导入放到需要推断、审计或分析结果的端点调用路径内。目录、概览、样本等参考数据端点继续使用参考数据服务。

导入提前到启动时的成本将转移到第一次相关请求，因此必须同时测量服务启动与首个分析请求。若服务的其他模块已导入同一统计库，实际收益可能有限，应由导入计时决定是否保留该改动。

### 4.3 数据库迁移快速检查作为后续小项

`prepare_runtime()` 与 FastAPI lifespan 都调用 `upgrade_database()`。保留所有独立启动入口的迁移能力，在共享迁移函数中考虑增加真实数据库版本检查：只有版本已明确等于代码 HEAD 时快速返回；旧库、无版本记录及异常状态按现有逻辑处理。

实现前确认这次检查本身的成本和事务行为，不采用磁盘标记文件代替数据库状态，不把数据准备放到请求已经开始后执行。分别覆盖 SQLite、MySQL、新数据库、已更新数据库和失败场景。

GMrepo 当前完整校验开销很小，继续保留其完整性验证与自动接入行为。

## 5. 第四阶段：整理启动模式和运行环境目录

### 5.1 开发、演示与部署入口

| 使用场景 | 前端运行方式 | 设计要求 |
| --- | --- | --- |
| 修改 React 页面 | Vite 开发服务，端口 3000 | 使用第一阶段配置，保留热更新 |
| 本地演示、查看构建结果 | 构建后启动 preview，端口 4173 | 复用现有 `/api` 代理；显示当前构建状态 |
| 正式部署 | 静态服务器提供 `dist` | SPA 路由回退和 API 反向代理由部署配置管理 |

可在 `Start-ADMeta.ps1` 中增加 `build`、`preview` 入口。构建与启动预览分开执行，便于复用已有产物；缺失产物或入口文件时明确提示构建。源码更新后提示重新构建，避免演示旧界面。`vite preview` 仅用于本地预览，不作为正式生产服务。

启动脚本显示实际 URL、Node 版本及模式。开发与预览端口可设置 `strictPort`，端口被占用时明确失败，避免浏览器继续打开另一份旧服务。

### 5.2 运行环境路径迁移

长期建议将本地运行环境放在项目根部 `.tmp/runtime`，从结构上离开前端根目录。

先实现统一的路径解析，优先级为：显式环境变量指定路径、新目录、现有 `frontend/.tmp/runtime`。统一用于 Node marker、Rscript、R library、renv 等路径，并同步 runbook。

第一阶段的目录忽略配置已经能够处理旧目录。后续迁移时先验证新环境可用，再切换入口；R/renv 的链接、库路径和配置可能引用旧位置，需要重建或重新配置。旧目录在新环境通过 Node、worker 和依赖检查后再由维护者清理。

## 6. 性能测量和验收

增加独立的本地启动基准脚本，运行结果保存到被忽略的输出目录。现有 Playwright E2E 使用构建加 preview，不能替代 Vite 开发冷启动检查。

测量应分别记录：

- 从发起启动到端口能接收请求的时间。
- HTML 响应时间与浏览器首次内容绘制时间。
- React 页面标志首次可见时间、首页入场动画完成时间。
- 原始页面导航期间的后端 API 请求数。
- 后端包校验、准备模块导入、迁移/同步、API 模块导入和健康接口可用时间。

前端至少覆盖三种条件：全新的临时依赖缓存首次加载、复用依赖缓存但重启服务、同一服务再次导航。每种条件至少 3 次；优化前后交错运行，记录中位数和最大值。样本较少时不报告 P95。

统一使用启动脚本的 Node、相同浏览器版本与页面尺寸；固定后端状态和浏览器缓存条件。OS 文件缓存的影响单独说明。测试只创建独立缓存，不清空用户现有 `.vite` 或业务数据缓存。

| 验收项目 | 初始目标 |
| --- | --- |
| 优化后的开发服务：新依赖缓存，导航到首页标志可见 | 本机重复测试中位数不超过 5 秒 |
| 同一服务再次导航 | 中位数不超过 1 秒 |
| 首屏启动提示 | HTML 返回后即可绘制，脚本延迟期间可见 |
| 运行环境监听 | `.tmp/runtime` 子目录监听数量为 0 |
| 首页后端依赖 | 首页加载期间后端 API 请求数量为 0 |
| JSX/CSS 热更新与页面功能 | 正常；GMrepo 和分析工作区直接导航可用 |
| 后端已有数据准备 | 按分阶段计时证实减少无用导入；不重建已发布数据 |
| 后端首次初始化、完整性、迁移与就绪检查 | 功能与错误语义保持正确 |

上述性能数字是实施后的验收目标。后端整体启动目标在阶段计时完成后设定，避免把某个模块导入时长当作完整启动时长。

先运行与改动相关的检查；涉及后端准备或迁移时，覆盖对应测试和数据库场景。第一阶段以监听、热更新、导航和开发模式基准为主，不新增只验证配置字面值的测试。

## 7. 实施顺序和回滚

1. 提交 A：Vite 文件范围配置与开发模式基准；先确认实际速度收益。

3. 提交 C：后端轻量准备与按需导入；分别评估启动和第一次分析请求的成本。
4. 提交 D：构建/预览入口、兼容路径解析和文档；运行环境迁移单独验证。

数据库迁移快速检查仅在计时显示值得优化且对应测试可覆盖时加入提交 C，或另作独立提交。

## 9. 实施与验收记录

- `vite.config.js` 指定入口，排除临时目录监听，并固定开发与预览端口。
- HTML 提供启动提示；15 秒后显示等待说明；启动脚本失败显示刷新入口。React 首次提交结束计时与事件监听，渲染异常由顶层错误界面处理。
- `DEFAULT_MANIFEST` 提取到轻量模块；bootstrap 的导入/预计算在执行导入时才加载；GMrepo 分析服务在相关端点请求时加载。
- 启动脚本增加 `build`、`preview`、`benchmark`，运行环境支持显式目录、新目录、旧目录依次解析。现有运行环境未移动。
- 原有数据库迁移逻辑保留。本次已有数据准备的主要收益来自导入减少，未扩大为迁移逻辑改造。
- 浏览器通过正常加载、慢加载、脚本失败刷新恢复、JSX/CSS 热更新、后端不可用时直接进入 GMrepo 和分析页面的检查。构建后的入口脚本失败提示与刷新恢复也通过；测试兼容 Vite 构建时移除原脚本 ID 的行为。
- Node 22.23.3、1440 × 960、减少动态效果、每次导航新浏览器上下文，三轮隔离缓存测量：新依赖缓存中位数 1,562 毫秒（最大 1,981）；同一服务再次导航中位数 219 毫秒（最大 231）；复用缓存后重启中位数 367 毫秒（最大 381）。首页 API 请求数与临时目录监听数均为 0。
- 一轮后端准备模块导入约 0.78 秒，随后 API 模块导入约 2.07 秒；预计算与 GMrepo 推断模块均未被提前加载。此处 API 时间是在准备模块已加载后的增量值，不能与全新进程总启动时间直接比较。
- 独立进程各三次导入复测：准备模块中位数 0.785 秒，API 模块中位数 2.972 秒。真实 GMrepo 目录接口返回 200；首次审计请求约 0.149 秒，重复约 0.012 秒，均返回 200。
- 前端相关 10 项测试、构建、类型检查及修改文件的 lint 通过；后端相关 46 项回归中 45 项通过。剩余的原有 ZIP 反斜杠路径测试在 Windows 上因 `ZipInfo` 将路径规范化而得到不同拒绝文案，安装器仍拒绝该包且本次未修改安装器。
- OpenAPI 与后端修改模块的类型检查通过。运行环境解析的旧目录、新目录、显式目录和缺失目录场景通过。
