# PCA / PCoA 排序分析模块统一优化方案

## 文档状态

- 状态：待实施方案
- 记录日期：2026-08-13
- 适用范围：物种丰度矩阵的 PCA 与 PCoA 分析、展示、解释性资源及审计信息
- 实施原则：后端负责科学计算，前端负责交互与呈现；任何解释性表格必须与当前排序结果绑定同一计算身份
- 版本关系：本文整合并扩展《PCA / PCoA 解释性表格后续实施方案》，作为后续实施与验收的主入口；旧文档保留为设计依据和历史记录

> 本文是实施方案，不表示相关功能已经全部上线。开发时仍以代码、API 和测试的实际行为为准。

## 1. 背景与问题

PCA 和 PCoA 当前都能完成样本排序并绘制散点图，后端也已分别实现各自的计算策略。但从长期开发角度看，仍存在两类需要一并解决的问题。

### 1.1 展示容器缺少清晰契约

PCA、PCoA 在图表注册表中仍使用通用的 `layout: 'special'`。这个名称没有表达排序图需要的实际布局语义，也没有明确规定：

- 绘图区应如何使用卡片剩余空间；
- 横纵坐标单位比例应如何保持；
- 图例、坐标轴标题、范围说明和折叠区应占用多少空间；
- 不同显示器尺寸下如何避免拉伸、裁剪或大面积无效留白；
- 图表更新后何时触发 ECharts `resize`。

结果是 PCA、PCoA 虽然使用同一个 `OrdinationChart`，但卡片、视口和绘图区之间没有形成稳定的尺寸关系，容易在笔记本、大屏显示器或折叠区展开后出现比例和留白异常。

### 1.2 科研解释能力不完整

当前排序图主要返回并展示二维样本坐标。已有实现能够提供部分解释信息，但尚未形成完整、可追溯的资源体系：

- PCA 尚未向前端正式提供主成分贡献物种、完整主成分解释率和特征筛选明细；
- PCoA 已在后端计算 PERMANOVA、PERMDISP 和特征值诊断，但尚未将样本到组质心距离等信息组织为独立资源；
- 当前“查看当前图表数据”仍容易退化成泛化的“系列 / 项目 / 数值”结构，不能充分表达排序分析语义；
- 排序图、解释表、筛选审计和统计检验需要统一绑定同一分析范围、参数、数据版本和计算版本。

## 2. 当前计算基线

后续优化不得改变下列已经确立的科学边界，除非另有经过评审的分析策略变更。

### 2.1 PCA

- 从当前样本范围中按总丰度选择 Top N 物种；
- 对入选物种逐列进行 Z-score 标准化；
- 在标准化矩阵上计算二维 PCA；
- 返回样本 PC1、PC2 坐标及对应解释率；
- 当前仍属于探索性排序，不包含批次、年龄、性别等协变量校正。

### 2.2 PCoA

- 对样本丰度矩阵进行非负值与有限值检查；
- 先按样本总量闭合为相对丰度；
- 使用与分组标签无关的相对丰度和检出率规则筛选物种；
- 以筛选后的同一矩阵计算 Bray-Curtis 距离；
- PCoA 坐标、PERMANOVA 和 PERMDISP 使用同一距离矩阵；
- 保留正、负特征值诊断及距离矩阵指纹；
- 单组范围不计算组间 PERMANOVA；样本量不足时必须返回明确状态，而非伪造统计结果。

### 2.3 共同约束

- 支持全部样本、AD 组、NC 组和自定义子集；
- 图中实际范围必须以服务端返回结果为准；
- 旧结果可以在新结果加载时暂时保留，但必须明确标注“正在计算新范围，当前仍显示上一版本结果”；
- 不允许标题已经切换到新范围，而图中仍无提示地展示旧范围数据。

## 3. 优化目标

| 目标 | 验收含义 |
| --- | --- |
| 统一模块骨架 | PCA、PCoA 共用排序分析模块的框架、交互和资源入口，不复制页面结构 |
| 保留方法差异 | PCA loading 与 PCoA 距离诊断分别实现，不把概念互相套用 |
| 稳定尺寸契约 | 图表在笔记本和大屏上均不拉伸、不裁剪，坐标几何比例可信 |
| 完整解释资源 | 样本坐标、主成分贡献、组内离散、特征值诊断和筛选审计各自有明确资源 |
| 计算身份一致 | 图、表、审计和检验始终绑定同一个 `projectionKey` 与参数版本 |
| 快速默认展示 | 默认范围可预热；打开解释表不重新计算整张排序图 |
| 可扩展 | 后续可接入 MAG 丰度矩阵、协变量模型和论文级导出，而无需重写图表骨架 |

## 4. 排序分析模块架构

建议将 PCA、PCoA 组织为同一个“排序分析模块”，而不是两个互不相关的特殊页面。

```text
OrdinationModule
├── OrdinationHeader
│   ├── 分析方法与科学说明
│   ├── 分析范围
│   └── 方法专属参数
├── OrdinationSummary
│   ├── 样本数
│   ├── 入选物种数
│   ├── 轴解释信息
│   └── 统计状态
├── OrdinationViewport
│   └── OrdinationChart
└── AnalysisResources
    ├── 当前排序样本坐标
    ├── 方法专属解释资源
    └── 筛选与计算审计
```

### 4.1 共享内容

- 样本范围选择；
- 服务端确认状态；
- 散点图、图例、缩放、重置和悬浮提示；
- 当前排序样本坐标；
- 筛选与计算审计；
- 缓存身份、加载状态和错误恢复；
- 卡片与图表视口契约。

### 4.2 方法专属内容

PCA 专属：

- 参与计算的物种数量；
- PC1、PC2 解释率；
- 主成分贡献物种；
- 特征标准化与筛选说明。

PCoA 专属：

- 距离类型和过滤预设；
- PCoA 轴解释率；
- PERMANOVA 与 PERMDISP；
- 组内离散及样本到质心距离；
- 正负特征值诊断；
- 过滤前后特征数量与闭合质量。

## 5. 图表容器与比例契约

### 5.1 注册表语义重构

不再以 `layout: 'special'` 表达 PCA、PCoA。建议把页面骨架和图表视口拆成两个正交配置：

```js
{
  frameLayout: 'analysis',
  viewportProfile: 'ordination'
}
```

- `frameLayout` 只负责卡片头部、控制区、正文和资源区的结构；
- `viewportProfile` 负责绘图区尺寸、长宽约束、内边距和响应式策略；
- PCA、PCoA 共用 `ordination` profile；
- 后续若 NMDS、RDA、CCA 上线，可复用同一 profile，而不复制 CSS。

### 5.2 真实可用空间测量

`OrdinationViewport` 应通过 `ResizeObserver` 读取容器实际宽高，并从卡片内容区扣除：

- 方法说明和状态摘要；
- 控制栏；
- 图例；
- 坐标轴标题及极值标签安全区；
- 资源折叠入口的固定衔接区。

不得通过多个页面分别硬写 `620px`、`680px`、`760px` 等高度解决问题。最小高度、理想高度和最大高度应由统一 profile 给出，最终绘图区由实测空间决定。

### 5.3 保持排序几何关系

PCA、PCoA 是距离和方向解释图，横纵坐标不能仅为“铺满卡片”而任意拉伸。

绘图区应遵守：

1. 根据当前 x、y 数据范围计算坐标跨度；
2. 在保留坐标轴、图例和标签安全区后，计算可用绘图区；
3. 尽量保持 x、y 相同的像素 / 数值单位，使样本间几何关系不被视觉扭曲；
4. 在卡片中居中放置满足比例的绘图区；
5. 剩余空间属于正常留白，但不能出现图形偏在顶部、底部或某一侧的失衡；
6. 极端离群值导致主体过小时，提供缩放和恢复能力，不静默裁掉离群点。

### 5.4 响应式策略

至少覆盖以下视口：

- 1366 × 768：笔记本常见尺寸；
- 1920 × 1080：常见桌面显示器；
- 2560 × 1440：27 寸高分辨率显示器。

响应式变化只允许调整：

- 图表可用宽高；
- 图例位置；
- 标签密度和字号档位；
- 控制栏换行方式。

不允许因屏幕变化而改变科学数据、筛选规则或统计检验结果。

## 6. PCA 功能优化

### 6.1 当前排序样本坐标

主表建议字段：

| 字段 | 含义 |
| --- | --- |
| 样本 ID | 稳定样本标识 |
| 分组 | AD / NC 或当前元数据分组 |
| PC1 | 第一主成分得分 |
| PC2 | 第二主成分得分 |
| 参与当前投影 | 当前样本是否进入模型 |
| 排除原因 | 未进入时的结构化原因 |

表头必须常驻，数值列支持排序，样本 ID 支持检索。表中不再使用“项目 1”“项目 2”等无科学语义字段。

### 6.2 主成分解释率

新增“查看主成分解释率”，至少返回：

| 字段 | 含义 |
| --- | --- |
| 主成分 | PC1、PC2，以及后续可配置的更多轴 |
| 特征值 | 该主成分的特征值 |
| 解释率 | 单轴解释率 |
| 累计解释率 | 从 PC1 累计到当前轴 |

图中仍默认显示 PC1、PC2，但资源表不应被二维显示限制。

### 6.3 主成分贡献物种

新增“查看主成分贡献物种”，建议字段：

| 字段 | 含义 |
| --- | --- |
| 物种 | 稳定物种 ID 与显示名称 |
| PC1 loading | 对 PC1 的带方向权重 |
| PC2 loading | 对 PC2 的带方向权重 |
| \|PC1 loading\| | PC1 贡献强度排序值 |
| \|PC2 loading\| | PC2 贡献强度排序值 |
| PC1 contribution | 归一化后的 PC1 相对贡献，可选 |
| PC2 contribution | 归一化后的 PC2 相对贡献，可选 |
| 入选依据 | 当前物种进入 PCA 的筛选原因 |

约束：

- loading 必须直接来自当前 PCA 模型；
- 不能从二维样本坐标反推物种 loading；
- 正负号表示方向，绝对值表示贡献强度，两者必须分列；
- 排序和筛选必须在后端执行，前端只提交轴、方向、排序字段和分页参数。

### 6.4 PCA 筛选审计

至少记录：

- 原始物种数；
- 参与计算的 Top N；
- 排序指标及其版本；
- 入选和未入选数量；
- Z-score 标准化范围；
- 零方差物种处理结果；
- 数据版本、计算版本和 `projectionKey`。

## 7. PCoA 功能优化

### 7.1 当前排序样本坐标

主表建议字段：

| 字段 | 含义 |
| --- | --- |
| 样本 ID | 稳定样本标识 |
| 分组 | AD / NC 或当前元数据分组 |
| Axis 1 | 第一排序轴坐标 |
| Axis 2 | 第二排序轴坐标 |
| 参与当前距离矩阵 | 是否进入当前距离计算 |
| 排除原因 | 未进入时的结构化原因 |

### 7.2 组内离散与质心距离

新增“查看组内离散”，建议字段：

| 字段 | 含义 |
| --- | --- |
| 样本 ID | 稳定样本标识 |
| 分组 | 当前检验使用的分组 |
| 到本组质心距离 | 在全部正 PCoA 轴空间中的距离 |
| 参与 PERMDISP | 是否进入离散度检验 |
| 排除原因 | 未进入时的结构化原因 |

约束：

- 到质心距离必须沿用当前 PERMDISP 的正轴空间；
- 不允许只使用图中 Axis 1、Axis 2 重新计算；
- 表格、PERMDISP 结果和图中坐标必须绑定同一距离矩阵指纹。

### 7.3 特征值诊断

新增“查看 PCoA 特征值诊断”，建议字段：

| 字段 | 含义 |
| --- | --- |
| 轴 | Axis 1、Axis 2 等 |
| 特征值 | 原始特征值 |
| 正负类型 | positive / negative |
| 正轴解释率 | 在正特征值总和中的占比 |
| 累计正轴解释率 | 正轴累计占比 |

摘要同时给出：

- 正特征值数量；
- 负特征值数量；
- 负特征值绝对值占比；
- 是否达到需要谨慎解释或考虑校正方法的诊断阈值。

### 7.4 过滤与闭合审计

至少记录：

- 原始物种数；
- 非负值和有限值检查；
- 样本闭合前后行和质量；
- 最低检出率；
- 最低相对丰度；
- 保留和排除物种数；
- 每个物种的检出率、最大相对丰度、处理结果和原因；
- Bray-Curtis 距离矩阵指纹；
- PERMANOVA、PERMDISP 使用的样本集合和状态。

### 7.5 暂缓的物种贡献解释

PCoA 不存在可以直接照搬 PCA loading 的“物种贡献值”。排序轴与物种的关联需要单独确定统计方法，例如相关分析、envfit 类方法或其他经评审的方法。

在方法未确认前：

- 不新增“PCoA 贡献物种”表；
- 不从样本坐标和物种丰度简单相关后就称为贡献；
- 可以在文档中保留后续扩展点，但界面不得表现为已完成能力。

## 8. 后端资源与 API 契约

### 8.1 计算结果与解释资源分层

主图 payload 只保留首屏绘图和摘要所需字段；较大的解释表通过独立资源接口按需读取。

建议资源：

```text
PCA projection
├── sample_scores
├── component_summary
├── feature_loadings
└── selection_audit

PCoA projection
├── sample_scores
├── dispersion_distances
├── eigen_diagnostics
├── filtering_audit
└── inference_summary
```

### 8.2 统一资源身份

每个资源响应必须包含或可追溯到：

- `projectionKey`；
- 数据修订版本；
- 计算版本；
- 图表类型；
- 精确样本范围或样本集合指纹；
- 分析参数；
- 创建时间；
- 距离矩阵指纹（仅 PCoA 相关资源）。

服务端必须拒绝把不同 `projectionKey` 的图、表和统计结果拼接到同一界面。

### 8.3 查询能力

解释性资源接口应支持：

- 服务端分页；
- 物种或样本检索；
- 指定列排序；
- 处理结果和原因过滤；
- 只返回当前投影版本的数据。

打开折叠表不得重新执行 PCA、PCoA、距离矩阵或置换检验。

## 9. 前端资源区与交互

### 9.1 统一入口结构

PCA、PCoA 使用同一个 `AnalysisResources` 骨架。入口按科学语义显示，不为追求数量强行一致。

PCA：

1. 查看当前排序样本坐标
2. 查看主成分解释率
3. 查看主成分贡献物种
4. 查看筛选与计算明细

PCoA：

1. 查看当前排序样本坐标
2. 查看组内离散
3. 查看特征值诊断
4. 查看筛选与计算明细

PERMANOVA 与 PERMDISP 摘要应位于图表摘要区，并可跳转到对应解释资源，不再塞入一个泛化数据表。

### 9.2 范围与状态隔离

- PCA、PCoA 各自维护自己的范围和方法参数；
- 从 PCA 切换到 PCoA 时，不直接套用上一个页面的临时选择；
- 返回某图时，可恢复该图已确认的最后一次状态；
- 只有点击“应用”后才产生新投影请求；
- 范围变化后关闭旧投影的展开表，避免旧表与新图同时出现；
- 加载新投影时保留旧图，但必须显示旧结果身份和加载状态。

### 9.3 椭圆与图例

- 置信椭圆必须明确标注为样本分布椭圆，而不是组间显著性结论；
- 单组范围只显示该组图例，不残留另一组点或椭圆；
- 提供显示 / 隐藏椭圆控制；
- 提供缩放、恢复和下载当前交互图能力；
- 图例、点、椭圆和统计摘要的颜色含义保持一致。

## 10. 缓存与性能

### 10.1 缓存对象

缓存以完整投影为单位，而不是缓存每次前端搜索结果：

- PCA 模型结果、样本得分、解释率和 loading 同批生成；
- PCoA 坐标、距离指纹、特征值、PERMANOVA、PERMDISP 和质心距离同批生成；
- 主图与解释资源共享同一投影身份；
- 表格查询只对已生成资源做分页和排序。

### 10.2 预热策略

可预热：

- 全部样本默认 PCA；
- 全部样本默认 PCoA；
- AD、NC 常用范围；
- 当前正式分析运行的默认参数版本。

自定义子集按需计算，并使用有容量和过期策略的缓存，不无限写入数据库。

### 10.3 失效规则

以下任一变化都必须形成新缓存身份：

- 数据修订版本；
- 样本集合；
- PCA Top N 或 PCoA 过滤预设；
- 标准化或距离方法；
- 计算代码版本；
- 置换次数和随机种子等统计参数。

## 11. 实施步骤

### 阶段 A：容器契约

- 在图表注册表中引入 `frameLayout` 与 `viewportProfile`；
- 新增 `ordination` 视口 profile；
- 通过 `ResizeObserver` 驱动 ECharts resize；
- 保持坐标单位比例并居中绘图区；
- 删除 PCA、PCoA 页面级固定尺寸补丁；
- 增加 1366、1920、2560 三档视觉回归检查。

### 阶段 B：PCA 解释资源

- 后端返回全部已计算主成分的特征值和解释率；
- 结构化返回 PC1、PC2 loading 与贡献排序值；
- 补充 PCA 特征筛选审计；
- 新增资源接口与分页查询；
- 前端增加解释率和贡献物种表。

### 阶段 C：PCoA 解释资源

- 暴露现有 PERMDISP 样本到组质心距离；
- 暴露完整正负特征值诊断；

- [ ] 正负特征值诊断可复现
- [ ] 单组和小样本范围返回正确统计状态

- [ ] 全部样本、AD、NC 和自定义子集的样本数正确
- [ ] 单组范围不残留另一组点、椭圆或图例
