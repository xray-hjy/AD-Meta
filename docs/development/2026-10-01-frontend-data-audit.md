# 前端页面与实际数据核查

核查日期：2026-10-01。范围：当前本机代码、已接入数据与 `http://127.0.0.1:3000` 实际页面。本文记录核查结论与下一轮修改建议；本轮未修改前端页面、数据矩阵或导入规则。

## 1. 当前结论

物种、群落 KO、MAG 三个工作区都已有实际数据和分析入口。当前主要缺口是数据来源、分析进度和版本说明未贯通到界面，部分首页状态已落后于实际接入情况。

默认范围实测均为 185 个样本，AD 122、NC 63：物种概览 9,819 个特征，群落 KO 2,258 个，MAG v3 有 872 个代表。MAG 来源页有 8,548 个成员关系。页面的当前范围与原始数据规模需要分别展示。

MAG 功能注释按用户最新确认属于 **待完成**。现有群落 KO 已交付，只是生成链路、单位和标准化方法待确认。两者进度分别记录。

## 2. 核查方式与覆盖边界

- 查阅项目生信流程参考、数据产品说明、NGDC 样本核对与服务器转交核对。
- 检查路由、分析域、图表注册、样本筛选、MAG 溯源、分类对应、完整结果等实现。
- 实测首页；物种丰度、门级组成、箱线图、差异热图、放射分类树、PCA、PCoA 入口；群落 KO 四个入口；MAG 丰度列表、分布、热图、分类、质量、来源、技术质控。
- 核对完成后的 PCA/PCoA、KO 相对贡献/检出/空差异结果，以及 MAG 各视图的数据与说明。部分视图首次打开时处于加载阶段，未将首次加载快照当成最终结果。
- 分类层级的旭日图、矩形树图、桑基图本轮检查注册和共享实现，未逐个进行最终绘制验收。
- 物种完整结果查询实测成功，显示 561,419 条已存储记录、数据版本 `2005c6a7f1554cebbb47632c81fe3bcb`、丰度口径 `unknown / unknown`。记录数是稀疏存储条数，不是完整矩阵单元格数。下载按钮和版本查询入口已存在，本轮未逐个下载文件或验收图形导出、分页、所有筛选组合及响应式布局。
- 使用独立临时浏览器标签页，保留用户原有标签页与筛选。浏览器本轮已捕获日志中的 error 列表为空；这不替代完整回归测试。

本机服务原先已停止，为核查启动了已配置的前端、后端与统计服务。

## 3. 页面对应的数据、问题与限制

| 页面 / 入口 | 实际输入与分析 | 能回答什么 | 当前限制或应补的说明 |
| --- | --- | --- | --- |
| 首页 | 静态分析域和流程介绍 | 平台有哪些分析入口？ | 缺少本批论文、项目、样本范围与版本摘要；流程图未区分参考流程和实际执行证据 |
| 物种丰度对比 | 当前物种矩阵的样本值 / 组均值、Top N | 哪些物种丰度较高？AD/NC 均值如何？ | 当前纵轴无确定单位；原始尺度未知；源 Excel 与服务器表差异未展示 |
| 门级组成 | 分类汇总后的组成占比 | 群落由哪些门组成？ | 应区分原始丰度与页面计算的组成比例，解释分母与 Other |
| 物种箱线图 | 当前范围按排名或指定物种的样本丰度 | 个体分布和离散程度如何？ | 不能把分布差异自动作为正式差异结论；原始尺度待确认 |
| 物种差异热图 | Mann–Whitney U、BH-FDR、log2FC 筛选 | 当前阈值下哪些物种有探索性组间差异？ | 默认 q<0.05、|log2FC|>1 实测无候选，页面准确显示无结果；不解释为疾病无关联 |
| 分类层级图 | 物种矩阵按分类父子关系汇总 | 门、纲、属、种如何组成？ | 放射树是分类层级展示；系统发育树需单独入口和数据 |
| PCA | 样本闭合、排名选特征、再次闭合、零值替换、CLR | 样本组成结构如何变化？ | 默认 50 个特征、185 点；探索性排序；分布椭圆不等于均值置信区间 |
| PCoA | 样本闭合、无标签过滤、Bray–Curtis；PERMANOVA/PERMDISP | 样本间组成距离及组间结构如何？ | 标准策略实测 331/8,777 特征、185 点；说明已有未校正检验与负特征值提示 |
| KO 丰度对比 | Sample × KO 的原始样本值 / 组均值 | 哪些 KO 丰度较高？ | 原始单位和标准化未知；不能作为某个 MAG 的功能归属 |
| 高丰度 KO | 每个样本总和归一化后计算组均值 | 当前矩阵内哪些 KO 贡献较高？ | 是矩阵内相对贡献；未展示 KO 不合并为 Other；不等于完整 KEGG 功能分类 |
| KO 检出率 | 当前矩阵值 >0 的比例与数量 | 各组有多少样本记录到对应 KO？ | 操作性检出定义已写明，不能等同实际生物学检出限或功能表达 |
| KO 差异特征 | Mann–Whitney U、BH-FDR、秩效应量 | 哪些 KO 有探索性组间差异及方向？ | 默认 q<0.05、最低检出比例 0.1 实测无显著 KO；页面明确不回填未经校正候选 |
| MAG 丰度列表 / 分布 | CoverM 相对丰度 %、组均值、分布和探索性检验 | 哪些 MAG 丰度较高，个体分布如何？ | 候选列表包含全部 MAG，不代表全部显著；筛选不等于协变量校正 |
| MAG 样本热图 | 当前样本平均丰度排名、log10(1+丰度%) 颜色 | 高丰度 MAG 在样本中如何分布？ | 按疾病/批次排序、不聚类，说明已存在 |
| MAG 分类 | 全部 872 个代表的 GTDB-Tk 2.7.2/R232 分类 | 各分类下有多少 MAG？ | 展示数量而非分类丰度；不受样本筛选影响 |
| MAG 质量 | 全部 872 个代表的 CheckM2 1.1.0 | 完整度、污染率分布如何？ | 参考区间内实测 666 个；未宣称符合包含 rRNA/tRNA 等条件的 MIMAG 高质量标准 |
| 来源与去冗余 | dRep 成员→代表、来源样本、实际 ANI、GTDB/NCBI/Bracken crosswalk | MAG 来自哪里，与哪些成员有关？ | 已接入；crosswalk 观察标签来自本批 Bracken，尚不能自动绑定当前物种 Excel |
| 映射与丰度阈值 | 样本映射比例、丰度严格大于阈值的 MAG 数 | MAG 集合解释多少测序信号？ | 映射比例不是完整度或基因组覆盖度；丰度阈值不是生物学检出限 |
| MAG 功能注释 | 当前无正式可接入结果 | MAG 携带什么功能？ | 待完成；分析完成后接入 MAG→Gene→功能明细及实际评分/数据库 |
| 系统发育树 | 本机收到 GTDB 分类定位树，尚未接入前端 | MAG 在参考树中的位置 / 独立序列推断关系 | GTDB 树含参考基因组，独立 IQ-TREE 完成状态待确认；不能替用分类层级树 |
| 物种–功能联合 | 入口禁用，尚未实现 | 后续可研究同一样本中的关联 | 仍为规划中；相关关系不能充当功能归属 |

## 4. 下一轮优先修改清单

### A. 状态文字与范围一致性：可以立即处理

1. **统一 MAG 功能注释状态为待完成。** 首页当前写“规划中/待数据接入”，MAG 导航写“规划中”，就绪度又写“待核验”。按最新进度统一为“分析进行中，待完成”，并解释完成后交付结果。群落 KO 保持已接入。
2. **统一来源与去冗余状态。** 首页和分析域描述仍写“规划中/候选包待验收启用”；实际 MAG v3 来源页已启用，能查询 8,548 个成员、872 个代表及 crosswalk。首页需同步真实能力，原始包的历史说明保留。
3. **区分数据集规模与当前筛选规模。** 实测女性筛选 F 后，MAG 顶部显示“运行 115 样本 · 当前结果覆盖 115”，侧栏“总样本数”也为 115（AD 77、NC 38）。数据版本本身仍含 185 个样本。建议固定显示“数据集 185”，另显示“当前分析 115”。
4. **让顶部范围对应当前视图。** 在上述 F 筛选后切换 MAG 分类或质量，结果使用全部 872 个 MAG，图表说明显示 185 个样本，顶部仍显示运行/覆盖 115。分类、质量、来源视图应注明 MAG 层级与完整集合，顶部不能沿用丰度视图筛选后数量。数据未丢失，这是范围表述不一致。

### B. 数据说明与证据接入：无需等待学姐全部回复

5. **增加统一的数据总览与来源入口。** 每份产品登记：用途、样本/特征维度、版本、原始文件、单位、进度、来源核对状态；提供论文→PRJCA022804→CRA014435→当前 185 样本清单的关系。解释物种源表 373 样本、本轮 185 样本及导入规则，样本选择原因仍标待确认。
6. **让原始尺度待确认提示覆盖所有图表。** PCA/PCoA、KO 相对贡献等已有“上游标准化方式待确认”；物种与 KO 默认丰度对比没有该提示。代码原因是独立 abundance projection 未返回 `dataSemantics`，共享提示依赖该字段。应统一返回和展示“原始单位待确认/上游标准化待确认”；页面自己的归一化规则另外说明。
7. **把已核验上游证据绑定到数据版本。** MAG 展开的溯源目前仍提示“未附带已核验的上游生成参数”。本次整理已对上 CoverM 成功脚本/日志、CheckM2、GTDB 实际运行记录；需要通过独立、可追溯的证据登记关联到 v3，不修改原始交付文件或用静态文字假定全部流程已核验。dRep 精确执行版本和前处理等未知项保留。
8. **限定 crosswalk 的观察范围。** 页面已有“分类标识符对应，不证明 reads 比对到 MAG”的说明；再明确其来源 Bracken 批次与输入版本，以及“当前 Excel 尚未对齐”。对应表可继续查询，不能直接据此声称当前物种矩阵中不存在某个物种。

### C. 需要进一步核查或等待上游的事项

9. **解释不同图的物种特征分母。** 概览与丰度对比使用 9,819，多个通用分析投影使用 8,777。代码中后者由数据库丰度记录构建矩阵，前者读取产物登记特征数。本轮未逐列证明 1,042 个差额全部为全零特征；应进一步对照特征目录与稀疏存储，明确“原表特征数/已存储特征数/当前范围非零特征数/参与计算特征数”，再决定是否修改计算或只补说明。
10. **学姐回复后决定物种/KO 的正式数据版本。** 等待当前 Excel 来源差异、群落 KO 生成方法/单位、纳入和排除依据及元信息解释。当前文件与服务器新批次均保留；不要为统一页面而直接覆盖矩阵或猜测单位。
11. **树与 MAG 功能后续分别接入。** MAG 功能分析待完成；独立 IQ-TREE 进度另行确认。GTDB 分类定位树可先定义接入方案，但需标注方法、参考叶节点、869 个当前细菌 MAG 覆盖范围及古菌对应树未交付。功能接入字段按真实工具产物确认，先整理交付契约。

## 5. 建议实施顺序

1. 状态修正与 MAG 样本范围表述统一。
2. 三类数据的统一总览、来源说明与单位/版本提示。
3. 将已核验服务器运行证据关联到 MAG v3，并限定 crosswalk 批次。
4. 学姐回复后完成物种/KO 方法登记；功能产物完成后接入，树按独立进度推进。

当前图表的筛选审计、KO 相对贡献规则、无显著差异时的准确空结果、MAG 质量边界和技术质控说明应保留。新增界面以回答研究问题和解释数据为主，文件校验值及完整命令可放到可展开的证据详情。
